MCP 服务器和 Skill 扩展 Agent 能做什么、知道什么。两者都在配置中心里管理，都是**逐 Agent 启用**的。

## MCP 服务器

MCP（Model Context Protocol）服务器为 Agent 提供额外工具。Vibex 支持三种传输方式：

| 传输 | 适用场景 |
| --- | --- |
| **stdio** | 本地进程。填写启动命令、参数和环境变量。 |
| **HTTP** | 远程服务。填写 URL 和请求头。 |
| **SSE** | 远程服务，Server-Sent Events。填写 URL 和请求头。 |

### 从市场安装

打开 **配置中心 → MCP**，默认进入 **MCP 市场**：

1. 搜索或分页浏览。卡片显示传输方式、来源、命令摘要和已启用的 Agent。
2. 点 **安装**，先确认将要保存的命令、传输方式、环境变量和请求头。
3. 选择哪些 Agent 接收这个 MCP 服务器。
4. 安装完成后，条目会出现在左侧的已安装列表里；可以 **重新安装** 或编辑。

<Note>
  市场搜索会边输入边查上游目录。安装前请确认服务器来源和命令；市场条目不是 Vibex 背书的可执行文件。
</Note>

### 手动添加

1. 在 MCP 列表点击 **新建 MCP 服务**。
2. 填写 **名称**，选择传输方式。
3. 按传输方式填写 **命令** / **参数** / **环境变量**，或 **URL** / **请求头**。
4. 选择作用域：**用户** 或 **工作区**。
5. 保存，然后在资源卡片上点击 **验证**。
6. 在卡片下方的 **Agent 启用范围** 区域，为需要使用它的 Agent 打开开关。

也可以使用 **导入已有 MCP** 从其它 Agent 的原生配置里读取候选。导入会先显示预览，不会静默覆盖。

<Info>
  校验是**离线**的：它只检查必填字段和 URL 格式（HTTP/SSE 必须以 `http://` 或 `https://` 开头），不会启动进程，也不会发起网络请求。所以校验通过不代表服务器真的能连上。
</Info>

<Warning>
  MCP 工具可能读取文件、访问网络或修改外部系统。先确认服务器来源和权限，再把它关联到 Agent。
</Warning>

## 技能

Skill 是一份 `SKILL.md` 加上它引用的辅助资源，用来给 Agent 补充可复用的领域知识或操作流程。来源可以是：

| 来源 | 说明 |
| --- | --- |
| `manual` | 直接在 Vibex 里手写。 |
| `local_folder` | 本地文件夹。 |
| `git_repo` | Git 仓库。 |
| `marketplace` | 市场来源。 |

### 从市场安装

打开 **配置中心 → Skill**，默认进入 **Skill 市场**：

1. 搜索或分页浏览。卡片显示来源、安装量、官方标记和已启用的 Agent。
2. 点 **安装**，在提交前阅读完整的 `SKILL.md` 正文、文件清单和被拒绝的文件。
3. 选择哪些 Agent 接收这个 Skill。
4. 安装完成后可以 **重新安装**；被撤下的条目会优先说明。

### 手动添加

1. 打开 **配置中心 → Skill**，点击 **新建 Skill** 或 **导入已有 Skill**。
2. 填写 **名称**、**描述** 和 **技能说明**（也就是 `SKILL.md` 的正文）。
3. 保存并 **验证**。
4. 在 **Agent 启用范围** 里为需要的 Agent 打开开关。

配置好后，在输入框中输入 `$` 就能查找并插入已启用的 Skill。

<Warning>
  Skill 的正文和附带文件会进入 Agent 的上下文。安装前阅读内容，尤其是来自市场的 Skill；不要安装会要求凭据或执行未知命令的条目。
</Warning>

## Prompt

Prompt 是配置中心里的另一种可复用资源，适合反复输入同一段指令：

- 在 **配置中心 → Prompt** 新建，填写名称和正文。
- 在输入框里输入 `/` 搜索并插入。
- Prompt 也可以按 Agent 启用。
- Prompt 是纯文本，不携带文件或工具；需要这些时用 Skill。

## 导出到 Agent 原生配置

MCP、Skill 和 Prompt 都可以写入 Agent 自己的配置文件，这样 Agent 的其它入口（例如外部 CLI）也能用上同一份配置。

在资源卡片上使用 **预览导出** → **应用** → **回滚**：

1. **预览导出** 会列出将要改动或新建的文件。
2. 确认无误后再 **应用**。
3. 出问题时从同一处 **回滚** 恢复。

写入目标取决于 Agent，例如 Codex 的 `~/.codex/config.toml`、Claude 的 `~/.claude/settings.json`，以及各 Agent 的技能目录。

<Warning>
  **应用之前一定要看预览。** Vibex 默认不改写 Agent 的原生 home 配置，只有你明确应用时才写入。
</Warning>

## 作用域与安全

使用最小作用域，避免把项目专属工具暴露给所有项目。MCP 服务器当前只提供 **用户** 和 **工作区** 两种作用域。

- 先停用，再删除；停用会保留记录，便于恢复。
- 删除资源不会删除已经写入 Agent 原生目录的文件；用导出预览里的回滚处理。
- 任何日志和诊断资料都必须去掉 token、私钥、环境变量值、提示词和文件内容。
- 市场安装会写入运行时 home；不要把不受信任的市场条目直接启用给所有 Agent。
