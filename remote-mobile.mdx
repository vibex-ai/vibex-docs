---
title: "远程访问与移动端"
description: "将移动端配对到桌面运行时，并安全地查看和操作会话。"
---

移动端是桌面端的原生远程伴侣。桌面端仍负责 Agent、文件、Git、PTY、供应商和权限；移动端通过 Remote v2 请求投影和操作，不会运行本地 Agent。

## 选择连接方式

| 方式 | 适用场景 |
| --- | --- |
| **Direct** | 手机和桌面端可直接通过局域网或可达地址连接。 |
| **Tailnet** | 你使用 Tailscale 等私有网络，桌面端不暴露公共端口。 |
| **Self-hosted Relay** | 桌面端和手机无法直连时，通过自托管 Relay 转发加密帧。 |

Relay 不保存或解密业务数据。它只处理房间、连接和加密帧等路由元数据。

## 配对

1. 在桌面端打开远程配对，选择 Direct、Tailnet 或自托管 Relay 候选。
2. 生成有效期很短的一次性 QR 或 deep link。
3. 在手机上扫描或打开 `vibex://open/...` 链接。
4. 确认设备名称、工作区范围和权限级别。
5. 完成握手后等待桌面端发送初始投影和会话列表。

QR/deep link 不包含长期 grant、供应商密钥、私钥或工作区内容。不要把它发布到聊天、Issue 或其他公开渠道。

## 权限级别

- **read_only**：查看会话、文件摘要、Git 状态/差异和供应商摘要。
- **approve_only**：在允许的范围内处理权限审批，不直接执行普通写操作。
- **full_control**：可发送消息、写入文件、执行终端输入和 Git 写操作，仍受桌面端能力门控。

授予最小权限。桌面端可以随时撤销设备；撤销会立即结束该设备的活动连接。

## 移动端可做什么

你可以查看结构化 Agent 时间线，发送后续消息，填写 elicitation 表单，批准或拒绝请求，查看文件和 Git 状态，并在权限允许时使用远程终端。文件编辑和 Git 操作的真实结果始终来自桌面端。

## 断线与重连

网络切换或应用恢复后，移动端会重新认证并请求 catch-up。先显示权威会话和时间线状态，再恢复实时事件。若看到 stale、revoked 或 resync required，按提示重新配对或在桌面端检查 Remote gateway。

## 安全检查

保持 Remote gateway 默认关闭或仅绑定 loopback；通过 Tailnet 或受控 HTTPS/WSS 代理发布。不要使用公共未认证监听，也不要把 room id 当作权限凭据。
