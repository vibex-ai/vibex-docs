**配置中心**是 Vibex 的配置入口，从侧栏的 **配置中心** 按钮或系统托盘打开。它把 Agent 运行时、模型供应商、MCP 服务器、Skill 和可复用 Prompt 集中在一处，并为每项资源显示状态和验证结果。

## 分区

配置中心当前提供五个主分区：

| 分区 | 用途 |
| --- | --- |
| **Agent** | 添加、安装、升级、登录和管理 Agent 运行时；在所选 Agent 的详情里配置它自己的**模型供应商配置**。 |
| **供应商** | 管理共享 Provider、Key、模型、路由组和本地模型网关。 |
| **MCP** | 从市场安装或手动添加 MCP 服务器，并逐个 Agent 启用。 |
| **Skill** | 从市场安装或导入 `SKILL.md` 能力包，并逐个 Agent 启用。 |
| **Prompt** | 编写可复用 Prompt，在输入框里用 `/` 插入。 |

<Note>
  **模型供应商配置**不是独立分区。每个 Agent 可以有自己的模型供应商配置；**共享供应商**和**路由组**在 **供应商** 分区里。两者的关系见[供应商、路由组与本地网关](/providers-and-gateway)。
</Note>

## 通用操作

### 搜索与筛选

每个分区的左侧列表顶部都有搜索框。Agent 可以按名称、id 和描述搜索；供应商可以按名称、地址、模型和 Key 搜索；MCP、Skill 和 Prompt 可以按名称或描述搜索。列表会记住你的排序和筛选，直到你改变它。

### 保存与验证

1. 填写字段并保存。
2. 在资源卡片上点击 **验证** 运行校验。MCP 和 Skill 的校验是**离线**的：检查必填字段、格式和作用域，不会启动进程或发起网络请求。
3. 对模型供应商可以额外运行 **测试连接**，它会真实调用一次模型接口。

<Warning>
  **测试连接**、**拉取模型** 和真实会话都会访问供应方网络并可能产生费用。确认地址、模型和权限后再运行。
</Warning>

### 作用域

部分资源可以设定作用范围：

- **用户**：对你所有项目可见。
- **工作区**：只对当前工作区可见。
- **项目**：跟随项目约定（部分资源支持）。
- **全局**：作为全局默认，谨慎使用。

开始配置时先选最小作用域。MCP 服务器当前只提供 **用户** 和 **工作区** 两种。

### 逐 Agent 启用

资源（MCP、Skill、Prompt、Provider）和 Agent 之间是**逐 Agent 启用**的关系。资源卡片下方的 **Agent 启用范围** 区域为每个已添加的 Agent 提供一个开关；只有打开开关的 Agent 才会加载该资源。

不需要某个资源时先**停用**，而不是立刻删除——停用会保留记录，便于之后恢复。删除资源会移除配置，但不会删除已经写入 Agent 原生目录的文件；需要时用导出预览里的回滚。

### 凭据

Vibex 使用 secret reference 或操作系统的安全存储保存凭据。桌面端优先使用系统钥匙串；没有可用钥匙串的主机退回仅属主可读的文件。

- 已保存的 Key 默认掩码显示，点眼睛图标可以临时查看。
- 没有改动过的字段不会重写已保存的值；留空保存会保留原值。
- 要清除凭据，使用明确的 **清除** 操作，而不是把输入框留空。
- 不要把 token、私钥、完整环境变量、提示词或文件内容粘贴到配置描述或诊断日志中。

## Agent 分区

左侧按状态分组：已启用、已添加但停用、尚未添加。每个 Agent 的详情包含：

- **Agent 安装**：安装、检查更新、升级、回滚到固定版本、卸载托管运行时。
- **原生凭证**：登录 Agent 自己的账号，刷新认证方式、验证账号、刷新模型、重新认证、退出登录。
- **模型供应商配置**：这个 Agent 自己的地址、凭据、模型和思考档位。
- **内置工具**：按 Agent 开关终端、浏览器、电脑操作等工具面板。

详见[Agent 与供应商配置](/agents-and-providers)。

## 供应商分区

**供应商**页把每个共享 Provider 只列一次，并显示哪些 Agent 正在使用它。顶部固定一行是**网关**，侧栏有 **供应商** 和 **路由组** 两个标签。

- **供应商**：地址、凭据、Key、模型、请求头、代理、请求体字段。
- **路由组**：把多个 Provider 或模型组合成一个 Agent 可请求的名字，设置策略、故障转移、限制和可见性。
- **网关**：本机回环端点，负责路由、协议转换、冷却、重试和请求台账。

详见[供应商、路由组与本地网关](/providers-and-gateway)。

## MCP 与 Skill

两个分区默认打开**市场**，可以直接搜索、分页浏览和安装：

- **MCP 市场** 显示传输方式、命令、环境变量和请求头；安装前可以确认将要保存的命令。
- **Skill 市场** 显示 `SKILL.md` 正文、文件清单、安装量和来源；安装前可以阅读完整内容，并选择哪些 Agent 接收。
- 已安装的条目提供 **重新安装**；被撤下的条目会优先说明。
- 也可以 **新建** 或 **导入已有** MCP / Skill。

详见[MCP 与技能](/mcp-and-skills)。

## Prompt

**Prompt** 分区保存可复用的提示词正文。保存后，在输入框里输入 `/` 就能搜索并插入；Prompt 也可以按 Agent 启用。

Prompt 与 Skill 的区别：Prompt 是一段可插入的文本，Skill 是一个带文件和说明的能力包。需要给 Agent 增加工具或领域知识时用 Skill；需要反复输入同一段指令时用 Prompt。

## 导出到 Agent 原生配置

MCP、Skill 和 Prompt 可以写入 Agent 自己的配置文件，让外部 CLI 也能用上同一份配置。

在资源卡片上使用 **预览导出** → **应用** → **回滚**：

1. **预览导出** 会列出将要改动或新建的文件。
2. 确认无误后再 **应用**。
3. 出问题时从同一处 **回滚** 恢复。

写入目标取决于 Agent，例如 Codex 的 `~/.codex/config.toml`、Claude 的 `~/.claude/settings.json`，以及各 Agent 的技能目录。

<Warning>
  **应用之前一定要看预览。** Vibex 默认不改写 Agent 的原生 home 配置，只有你明确应用时才写入。应用后可以从同一处回滚。
</Warning>

## 配置出现问题时

1. 确认资源的作用域和启用状态。
2. 运行 **验证** 看是否有结构化错误。
3. 确认该资源已在目标 Agent 的 **Agent 启用范围** 里打开。
4. 检查当前连接的是哪个权威运行时——本机和远程运行时的配置是分开的。
5. 如果重启后状态不一致，见[故障排查](/troubleshooting)。不要直接删除 SQLite 数据库。
