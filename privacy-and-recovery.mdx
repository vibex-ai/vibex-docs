description: "了解 Vibex 的本地存储、重启恢复行为、备份方式和诊断数据边界。"
---

Vibex 采用本地优先模型：权威运行时保存项目、工作区、会话、时间线、供应商配置、终端元数据、浏览器配置、电脑操作审计、路由台账和远程设备记录。远程连接只把获得授权的投影发送给客户端。

## 数据在哪里

| 数据 | 位置 |
| --- | --- |
| 权威元数据与会话状态 | 权威运行时 home 中的 SQLite 数据库 |
| 项目文件 | 你选择的本地目录，或 Vibex 托管的 Git worktree |
| 供应商凭据 | 操作系统的钥匙串；无头主机上退回仅属主可读的密钥文件 |
| Agent 安装 | 权威运行时的 home 目录 |
| 浏览器配置 | 运行时 home 下隔离的浏览器 `user-data-dir`；导入的登录状态也在其中 |
| 电脑操作记录 | 运行时 home 下的脱敏审计记录；不保存屏幕像素或输入文本 |
| 网关请求台账 | 运行时数据库；只含 token、延迟、状态和路由元数据 |
| TUI 偏好 | `~/.vibex/tui-interface.json`、`~/.vibex/tui-keys.toml`（或对应 home） |
| SSH / WSL 连接 | 桌面端 home 下的 `ssh-connections.json`、`wsl-connections.json` 和远端运行时注册表 |
| Relay 数据 | **无**。Relay 只转发加密帧，不保存业务数据库 |

Relay 的房间和连接是短暂状态。Relay 日志应只包含路由、计数和时序元数据。

## 重启后什么会保留

重启权威运行时后，它会根据持久化记录重新加载工作区、会话和配置。关键区别在于：

**会保留（写入 SQLite 或运行时 home）：**
- 项目、工作区和工作区模式
- 会话、时间线事件、消息、目标、委派关系和归档状态
- 供应商配置、共享 Provider、路由组、MCP 服务器、Skill、Prompt
- 终端**元数据**（标签名、绑定关系）
- 未发送的输入框草稿和定时发送
- 浏览器隔离配置、导入的登录状态
- 远程设备授权、SSH/WSL 连接配置
- 工作台背景、主题和 TUI 偏好

**不会保留（仅内存）：**
- 正在运行的 Agent 进程
- 终端**会话内容与滚动缓冲区**
- 浏览器打开的标签和实时画面
- 活动连接和实时事件订阅
- 正在进行的电脑操作会话

<Info>
  数据库里的 `running` 只是**上次观察到的状态**，不代表进程仍在运行。重启后看到 `running` 的会话时，先确认实际进程是否存在，再决定是否重试。
</Info>

丢失的终端会被标记为 `stale`。以新的终端快照为准，不要根据旧快照重复执行命令。

## 设备撤销

在权威运行时的设备列表中撤销设备后，该设备的活动连接会立即收到 `device_revoked` 并关闭。

- 重新使用需要**重新配对**。
- 旧的二维码、连接串、授权和 ticket 全部失效，不应继续使用。
- 撤销操作会写入设备审计记录。
- SSH/WSL 运行时只能通过桌面端的隧道访问，手机不能直接配对。

## 诊断数据

**设置 → 数据与诊断** 可以清理诊断数据。当前版本没有面向用户的诊断导出页面；如果你通过开发者工具导出诊断包，导出前请确认脱敏结果：

**必须移除：**
- token、私钥、配对码和连接串
- 提示词全文与文件内容
- Git diff 和终端原始字节
- 浏览器 Cookie、localStorage 和登录状态
- 电脑操作的输入文本、剪贴板内容和截图

**可以保留：**
- 版本、发布通道和平台
- 结构化错误码
- 脱敏后的时间戳
- 不敏感的资源 id

<Warning>
  诊断导出是**单向**的：一旦提交到公开渠道就无法收回。导出后请先自己读一遍再决定是否上传。
</Warning>

## 备份

Vibex 目前没有一键备份按钮。可靠的做法是备份整个**运行时 home**：

1. 关闭使用该 home 的运行时（桌面端、TUI 或无头服务）。
2. 复制整个 home 目录，包括 `vibex.db`、`vibex.db-wal`、`vibex.db-shm`、身份密钥、Agent 安装、浏览器配置和凭据引用。
3. 恢复时把备份放回一个空目录，再让运行时指向它。
4. 恢复后检查工作区路径、设备授权和供应商凭据引用是否仍然有效。

<Warning>
  只复制 `vibex.db` 而不复制 WAL/SHM 可能得到不一致的数据库。运行时正在写入时不要直接复制数据库文件。
</Warning>

无头运行时的数据默认位于 `/data`；把它挂载为持久卷，容器重建后会话才会保留。SSH/WSL 运行时的数据在远端 home 的 `~/.local/share/vibex/server` 下。

## 从候选版本导入数据

稳定版与候选版是两个独立应用，拥有各自的应用身份和数据目录（`desktop-stable` 与 `desktop-rc`），因此稳定版安装后从空数据开始。

要继承候选版本的工作，打开 **设置 → 数据与诊断 → 本地存储 → 从 RC 版本导入数据** 并确认：

1. Vibex 先对候选版数据库做快照。
2. 把快照迁移到当前版本的 schema，并校验副本。
3. 在下次启动时换入；工作区、会话与供应商配置一并带过来。
4. 导入失败时保留当前数据，不导入任何内容。

首次启动时如果检测到旁边的候选版数据，也会弹出一次提示，提供 **导入数据** 与 **暂不导入**。候选版安装本身永远不会被修改，因此可以继续把它作为退路。

<Warning>
  **导入是一次性的方向：候选版到稳定版。** 不要反过来把稳定版数据库拷进候选版目录，两者的 schema 可能不一致。
</Warning>

## 清理数据

**设置 → 数据与诊断** 中可以分类清理本地存储：会话与附件、终端数据、诊断数据。这些操作**不可回滚**。

浏览器数据可以在 **设置 → 浏览器 → 清除浏览器数据** 里单独清理；电脑操作记录和网关台账会随运行时数据一起保留，除非你清理对应数据库。

<Warning>
  重置设置只影响偏好；删除数据库、数据目录或工作区目录是不同的破坏性操作。执行前先确认你确实不再需要这些数据。
</Warning>

## 外部服务边界

Agent、MCP 服务器、共享 Provider 和浏览器页面可能把你明确提供的上下文发送到供应方或外部服务。使用前请阅读对应服务的隐私政策，并通过最小作用域、权限审批和最小附件控制数据范围。

配对到远程权威运行时意味着：**该权威运行时的管理员可以看到你的会话数据**。自托管时这个管理员就是你；连接到他人的运行时前请确认这一点。
