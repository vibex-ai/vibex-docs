---
title: "隐私与恢复"
description: "了解 Vibex 的本地存储、远程隐私和重启恢复行为。"
---

Vibex 采用本地优先模型：桌面端保存项目、工作区、会话、时间线、供应商配置、终端元数据和远程设备记录。远程连接只把获得授权的投影发送给移动端。

## 数据在哪里

- SQLite 保存权威元数据和可恢复的会话状态。
- 工作区文件仍在你选择的本地目录或 Git worktree。
- Agent、终端和 Git 进程由桌面端运行。
- 自托管 Relay 只转发加密帧，不保存业务数据库。

Relay 房间和连接是短暂状态。Relay 日志应只包含路由、计数和时序元数据。

## 重启和陈旧状态

应用重启后，桌面端根据持久化记录重新加载工作区、会话和配置。数据库中的 `running` 只是上次观察到的状态，不代表进程仍在运行。丢失的终端会标记为 stale；恢复前先检查实际进程和工作区。

<Info>
  看到 stale 或 resync required 时，先执行权威刷新，再决定是否重试。不要因为移动端暂时没有实时事件就重复发送有副作用的命令。
</Info>

## 设备撤销

在桌面端的远程设备列表中撤销设备后，活动连接会收到 revoked 状态并关闭。重新使用需要新配对；旧 QR、grant 或 ticket 不应继续使用。

## 诊断和备份

诊断和备份应经过脱敏：

- 删除 token、私钥、pairing code、提示词、文件内容、Git diff 和终端字节。
- 保留版本、平台、结构化错误码、时间和不敏感的资源 id。
- 备份 SQLite 前关闭桌面端或使用项目提供的安全备份流程。
- 恢复后检查工作区路径、设备授权和供应商 secret reference。

## 外部服务边界

Agent 和 MCP 可能把你明确提供的上下文发送到供应商或外部服务。使用前阅读对应服务的隐私政策，并通过 workspace 作用域、权限审批和最小附件控制数据范围。
