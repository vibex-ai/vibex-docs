---
title: "Agent sessions"
description: "Create, inspect, stop, fork, and resume Vibex Agent sessions."
---

A session stores task input, Agent output, and tool activity in a structured timeline. The desktop owns the authoritative timeline; mobile renders a remote projection.

## Create a session

1. Choose the target workspace.
2. Select an Agent, provider profile, model, reasoning depth, and conversation mode in Composer.
3. Enter a task. Use `/` for Prompts, `@` for workspace files, `$` for Skills, and attachments when needed.
4. Confirm the workspace and permission scope before sending. The Agent may request file, terminal, or other capabilities.

Switching an Agent or model affects later runs only. Timeline messages retain the identity of the run that produced them.

## Read the timeline

| Item | What it shows |
| --- | --- |
| User and Agent messages | Markdown text and attachments. |
| reasoning | An Agent reasoning summary, when exposed by the Agent and profile. |
| plan | Steps and progress. |
| tool/process details | Tool names, parameter summaries, processes, and exit results. |
| permission approval | A protected operation waiting for a decision. |
| elicitation | A typed form the Agent needs you to fill out. |
| delegation | Child Agent or delegated task state and result. |
| Status events | Running, queued, waiting, completed, failed, stopped, and reconnecting states. |

Tool parameters, terminal output, and diffs can contain sensitive data. Redact them before sharing.

## Control a run

- **Stop** stops the current run. It does not undo files or completed commands.
- **Continue** sends another task in the same session.
- **Retry** reruns a failed turn according to the Agent's retry semantics. Reconcile an uncertain external operation before retrying it.
- **Fork** creates a branch session from the current timeline.
- **Rename** changes the title without changing Agent context.
- **Edit message** changes a message that has not become the basis of a new run; completed timeline events remain immutable.
- **Resume** loads a persisted session after a restart.

<Warning>Stopping an Agent does not roll back file, Git, or external service changes. Inspect the diff and terminal separately.</Warning>

## Queue, auto-continue, and delegation

Follow-up messages sent while a run is active can enter a queue. The desktop shows their order and submits them after the current turn; canceling or deleting a queued item does not undo completed work.

With auto-continue enabled, only turns allowed by the session settings and Agent capabilities advance automatically. Permission requests, elicitations, failures, and choices that need you pause the run. **Delegation** creates an independent child state and links progress and the final result back to the parent session.

## Permissions and forms

When an Agent requests a terminal, file write, or protected capability, the timeline shows the reason and scope. Choose **Approve** or **Deny**; the result is recorded. Canceling an elicitation returns a cancellation result, not an implicit approval.

## Import local history

Use **Local history import** to scan local stores, then select sessions and a target workspace. Supported sources are Claude Code, Codex, OpenCode, Gemini CLI, Cline, Hermes, CodeBuddy Code, Kimi Code, Pi, Grok, Cursor, DeepSeek Harness, ZCode, and Google Antigravity.

The scanner keeps bounded metadata such as title, timestamps, workspace hint, message count, and source path. After you confirm, Vibex re-reads the selected source and materializes one atomic timeline import. Imported, deleted, and missing sources are reconciled without duplicate sessions. Credentials, private keys, and a complete Agent home are never imported.

## Search and notifications

Search the current timeline with `cmd-f` (usually `ctrl-f` on Windows/Linux). The desktop can notify you when a session completes, fails, or waits for input. Notification text is bounded and does not contain full messages or terminal output.

## Mobile sessions

Paired mobile clients can read the same timeline, send follow-ups, answer forms, and handle permitted approvals. They do not start a local Agent or own workspace files. Reconnection re-authenticates and catches up from authoritative state before live events resume; `resync_required` means the desktop must provide a fresh timeline.
