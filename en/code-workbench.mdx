The code workbench combines the file tree, search, editor, Git diff, and content previews. File operations stay within the selected workspace.

## File tree and search

1. Open the file tree in the sidebar.
2. Use filename search to locate a path.
3. Use content search to find text and its line location.
4. Open a result in a preview tab. Tabs can be arranged side by side or in splits.

Large files, undecodable content, and paths outside the workspace can be rejected by the file service.

## Edit and save

- Edit text directly in the editor.
- Select **Save** or press `cmd-s` (usually `ctrl-s` on Windows/Linux).
- Confirm the path before creating, renaming, or deleting a file.
- The editor persists soft-wrap and whitespace-display preferences, which you can toggle from the toolbar.
- **Save** carries the revision that was read. If an external process changed the file, saving pauses for a reload or diff instead of silently overwriting it.
- If an external process deletes the file, the editor marks it missing and keeps dirty content in a recovery buffer until you save it elsewhere or discard it.

<Warning>Deleting a file changes the workspace. Check Git status and create a recovery point before deleting.</Warning>

## Editor protection and recovery

Each editor buffer tracks saved content, the external revision, and a local revision. A save is accepted only while those values still match; a concurrent edit produces a conflict that requires a fresh read and an explicit merge decision. Before switching workspaces or closing a tab, the desktop checks dirty, save-pending, external-conflict, and missing-file states and blocks the action when needed.

After a restart or workspace reload, the desktop restores bounded dirty buffers. Restored content still requires an explicit save and never silently overwrites the file on disk.

## Content previews

| Type | Supported workflow |
| --- | --- |
| Markdown | Switch between editing and rendered views, including code, tables, formulas, and diagrams. |
| Images | View and edit images with undo and redo. |
| PDF | Use the native page preview. |
| Office documents | Preview supported Office content. |
| Other text | Open in the editor while preserving encoding and line endings. |

Binary files and files beyond the editor limits remain read-only. Markdown resources honor workspace paths, size limits, and resource-count limits; undecodable content is not forced into the text editor.

## Image editing

Image editing uses `cmd-z`/`cmd-shift-z` on macOS and `ctrl-z`/`ctrl-shift-z` on Windows/Linux. Confirm the output path and format before saving.

## Preview tabs and splits

Drag tabs or use the split control to inspect code, diffs, terminals, and documents together. Closing a tab does not delete its file or terminal; it closes only the current view.

## Common shortcuts

| Action | macOS | Windows/Linux |
| --- | --- | --- |
| Save file | `cmd-s` | `ctrl-s` |
| Open preview | `cmd-shift-p` | `ctrl-shift-p` |
| Sidebar | `cmd-b` | `ctrl-b` |
| Back/forward | `alt-left` / `alt-right` | `alt-left` / `alt-right` |

Review or change shortcuts in **Settings > Shortcuts**.
