## Highlights

* **Linux RPM packages** — x86_64 and aarch64 now ship `.rpm` beside the `.deb` and AppImage, repacked from the already reviewed `.deb` payload, and the updater manifest binds it as an `rpm/system_installer` artifact.
* **A shared Provider reaches every Agent** — editing a Provider on the Providers page now updates every Agent bound to it, instead of only the Agent the record was first derived from.
* **Codex honours your declared models** — an alias model with declared reasoning efforts or a context window is projected into a private Codex catalogue, so the effort is offered and the declared window applies.
* **WSL runtime setup shows its progress** — adding a WSL runtime reports each setup step and keeps the connection listed under **Remote connections** with its live status.
* **Remote Markdown images load** — `http(s)` images in a conversation and in a rendered document now fetch through the application's own HTTP client, capped at 32 MiB per response, instead of being blanked by the platform's refusing client.
* **Streaming costs less to watch** — while an answer streams, the desktop coalesces streaming-only timeline events and gates the sidebar and tab sweeps to a 30 fps budget.
* **Mobile session sync is lighter** — the phone fetches attachment bytes only when a picture is opened, and reasoning updates carry only the new delta.

## New features

**Linux packaging**

* `scripts/build-rpm.mjs` extracts the reviewed `.deb` data payload and drives `rpmbuild`, so the installed files, modes and embedded PDFium runtime stay byte-identical to the `.deb`; ELF `NEEDED` entries become portable SONAME requirements.
* The tagged publish job uploads the RPM, the release page lists its download, and the signed updater manifest carries it as a `rpm/system_installer` artifact.

**Desktop**

* A background update check no longer opens the title-bar panel by itself; the release surfaces through the title-bar entry and the panel opens on click, drawn as an in-tree layer so dialogs paint above it.
* Choosing **Connect WSL** reports the distro check, download, install, start, forwarding, pairing and connect steps as they happen, and keeps running if the dialog is closed; a failed attempt can be retried or inspected under **Remote connections**.
* A remote `http(s)` Markdown image or HTML `<img>` source loads through the application HTTP client, with bounded connect and request timeouts, at most ten redirects and a 32 MiB response cap.
* A rendered Markdown destination is classified before it is parsed as a URL: a `file:` URL or a drive path such as `C:\work\notes.md` opens as a local file, `http(s)` stays web, and any other scheme is unsupported.
* The title shimmer, streaming-only timeline batches and the sidebar and group-tab sweeps sit behind the 30 fps animation budget; reduced motion and an inactive window still render static.

**Providers and Agents**

* A Model added or edited on the Providers page fans out to each Agent's launch row and runtime profile, while each Agent still shows only the protocols it declares. Deleting a Model stays on the Providers page, so saving an Agent page no longer removes Models other Agents can still reach.
* Gateway-backed route groups and remote dispatcher writes republish the catalogue too, so a Provider edit, deletion or Key change refreshes every affected Agent, including writes from a paired device.
* Codex alias models are written to `vibex-models.json` beside the Profile's `config.toml`, listing every enabled Model with its declared context window and thinking levels; a Profile that declares neither keeps its previous output.
* A managed Agent install or rollback counts a stored snapshot as current only when it matches the new launch fingerprint, so new sessions no longer fail with `runtime_switch_configuration_unavailable`.
* A pi-acp model id that spells `<provider>/<model>` now carries the provider namespace and strips it on read-back, so a product id containing a slash is no longer rejected as `Model not found`.

**Mobile and remote**

* Timeline reads replace inline attachments with a bounded marker and fetch the detail item only when a picture opens; `agent_session` events are scoped to the open session, notifications only while backgrounded, and a gap is recovered with bounded catch-up pages.
* Reasoning chunks are sent as individual deltas, and inline attachment bytes are discounted from the timeline page budget.
* A remote timeline page is clamped to 512 KiB, leaving headroom for the E2EE envelope inside the Relay's WebSocket frame. The Relay's frame limit is exposed as `VIBEX_RELAY_MAX_WEBSOCKET_FRAME_BYTES` (default 2 MiB).

**Skills and Marketplace**

* The Install button stays live while a Skill folder is fetched and previewed, so a press on a large Skill is remembered and starts the install the moment the preview lands. The bytes written are still exactly the bytes the preview disclosed.
