## Highlights

* **First stable release** — `0.1.0` ends the candidate phase. The stable channel owns its own application identity and data directory, the `latest` container tag points at it, and the `vibex-bin` AUR package ships with it.
* **Real terminal sessions** — An Agent can run in its own CLI with a PTY carrying the conversation; thirteen Agents are verified, and the sidebar, search, notifications, mobile and TUI still work on the same session row.
* **One complete workbench** — Sessions, source, Git, terminals, an embedded browser, a local model gateway, Agent teams, goals and split-pane session groups live together, so context never has to be carried between tools.
* **Your runtime, your machine** — The authoritative runtime runs locally, on your own `vibex-server`, or on another machine the desktop provisions over SSH / WSL.
* **Three surfaces, one runtime** — The desktop, mobile, and the `vibex` terminal client drive the same authoritative runtime and install from the same release.
* **Ten languages** — English, Simplified Chinese, Traditional Chinese, Japanese, Korean, German, French, Spanish, Brazilian Portuguese and Russian.

## New Features

**Sessions and the workbench**

* A session runs one of two ways: an ACP session owns a timeline and a runtime binding, a terminal session starts an Agent CLI and records observation facts only; both are the same row in the sidebar, search and notifications (`35916d16`, `55c0c32d`)
* Session groups keep several sessions from one worktree together, with split panes, merged panes, whole-group auto-continue, drag into a folder and dissolve (`7348c84b`, `e6f49bd7`)
* The sidebar files drafts by folder, drops sessions into groups, and draws group members with branch guides (`7348c84b`, `0058ab32`, `cd6f299b`)
* Sidebar filters are a multi-select set, and sessions sort by creation, update, title or a manual arrangement (`125bea0c`, `7d99b489`)
* The command palette searches sessions, settings and quick actions from one query; session search indexes conversation text only and highlights the hit (`e30fdf14`)
* Goals publish through ACP's `_meta.goal` extension and normalise into the goal bar's phase, statistics and controls
* Delegation has a lifecycle: a task stays open, takes follow-ups, and is accepted or cancelled, with retries landing on the original acceptance
* Built-in tool panels are chosen per session, an absent entry follows the Agent, and a fork or delegation copies the map (`2acc9b7a`, `3866693d`)

**Terminal**

* Scrollback search covers every retained line, and previous/next scrolls a match into view (`9efd0d49`)
* Box Drawing characters are painted from their arms as joined vector lines, so tables and panel borders align across cells (`9efd0d49`)
* The bundled `Symbols Nerd Font Mono` stops an Agent's status icons painting as tofu (`9efd0d49`)
* Cell metrics come from the font's own advance, CJK still spans two columns, and ligatures are a preference you can turn off (`9efd0d49`, `bef85503`)
* OSC 52 clipboard, OSC 0/2 titles and colour queries, and the 1005, 1015 and 1016 mouse report dialects are answered (`9efd0d49`)
* The terminal background can be made translucent, and theme ink is lifted to a minimum contrast (`9efd0d49`)
* Terminal-mode CLIs receive MCP servers, Vibex delegation, the browser and computer use through the launch input each one reads, with credentials kept out of the argv (`06e89ac7`, `7b30af79`)

**Desktop**

* Twenty built-in light and dark themes, a theme mode that follows the system, and a window frame that can float (`f9e4bc2d`)
* The workbench background takes a still image, GIF or WebP, with fill, fit, stretch and an adjustable scrim
* The embedded browser is Chrome-backed, and Agents can read and drive the page
* The Provider workspace keeps the gateway, Providers and route groups in one place with a foldable sidebar and in-place editing (`9c5f2498`, `e2b94939`)
* Closing the main window is a two-way choice: keep running in the system tray, or quit (`6cc327a1`)
* The title-bar runtime panel is a switcher over paired instances, and remote instances always appear in navigation and search (`33571d2e`, `ce9d6afa`)

**Gateway and models**

* One loopback endpoint serves OpenAI Chat Completions, OpenAI Responses, Anthropic Messages and Google Generative AI, and translates between them (`6e7d1513`, `69dcf747`)
* A route is composed of `(Provider, model)` members, with seven strategies, a first-token deadline, and per-Key concurrency and rate caps (`3bec21f2`, `41956368`, `c166d3b8`)
* Presets ship as data and read model facts from the `models.dev` catalogue; a Provider you configured by hand can be saved as a reusable template (`f9dfd52c`, `c7e58564`)
* The request ledger records which route a request actually took, carrying ids and failure kinds only, and the live route map replays one request's path (`60974688`, `37193353`)
* Model capabilities are suggested from a maintained catalogue; context windows and thinking depths are declared data, never guessed from a model id

**Remote and mobile**

* The desktop installs `vibex-server` on a remote Linux or macOS host over SSH, opens a tunnel, pairs automatically, and rolls back a failed upgrade while keeping the runtime's identity (`4aa8b4a6`, `ec66c998`, `349d09bc`)
* A WSL2 distro works as a local Linux runtime with no sshd, and restores itself after `wsl --shutdown` (`6de4ca9e`, `4ccdd60a`)
* A Linux host without sshd can be bootstrapped with a one-time command that carries an expiry and verifies the payload hash (`c5df1c5c`, `bb67ef78`)
* Mobile pairs to the same runtime by QR code, then follows progress, answers questions, handles approvals and uses a terminal
* Mobile follows Reduce Motion, and an open session keeps its own workspace and conversation (`252329db`, `5d88cbf5`)

**TUI**

* `vibex` opens the current directory's new-session page with the directory and last-used runtime already filled in (`97ca1952`)
* The interface is one column of full-width bands that reflows at any terminal size, with no minimum size
* Every printed `key label` legend is a press target, and a press runs through the same dispatcher the keyboard uses (`7d031085`)
* The management page is the desktop-style Config Center, and the pairing page merges pairing, paired devices and remote access
* Language, theme and key bindings persist to `~/.vibex/tui-interface.json` and `~/.vibex/tui-keys.toml`

**Languages and localisation**

* The desktop, mobile and TUI all render ten languages; the seven added ones come from one shared catalogue, and an untranslated sentence falls back to English (`36d65e63`)
* The language picker lists all ten languages plus "System" on both clients (`36d65e63`)
* Korean spacing follows the bundled CJK face's real advances (`c1c421d3`)

## Performance

* A terminal resize fills the pane at once, and the whole paint pass is clipped to the grid's content mask (`9efd0d49`)
* Config Center writes, Provider probes, gateway reads and terminal starts run off the frame thread (`dfdaf81e`)

## Upgrading from a release candidate

Stable and RC are separate applications with their own data directories, so a stable install starts empty. To carry your RC work forward, open **Settings → Data & Diagnostics → Local storage → Import RC data** and confirm.

Vibex snapshots the RC database, migrates and verifies the copy, then swaps it in on the next start; your workspaces, sessions and Provider configuration come with it, and the current data is kept if the import fails. The RC install is never modified, so you can keep using it as a fallback.

On the first launch, RC data sitting next to the stable install also raises a one-time prompt offering **Import data** or **Not now**.
