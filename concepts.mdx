这一页解释 Vibex 里反复出现的几个词。读完它，其它页面会好懂很多。

## 权威运行时（runtime）

**权威运行时**是唯一持有真实状态的东西：Agent 进程、会话时间线、工作区文件、Git 仓库、终端、浏览器、电脑操作、供应商凭据和本地数据库。所有客户端都只是它的投影视图。

Vibex 里存在三种权威运行时形态，它们共用同一套内核，能力基本一致：

| 形态 | 说明 |
| --- | --- |
| **桌面端内嵌运行时** | 默认。随桌面应用一起启动，数据存在本机。 |
| **无头运行时 `vibex-server`** | 独立守护进程，跑在你自己的服务器或常开机器上。 |
| **SSH / WSL 远程运行时** | 桌面端通过 SSH 在另一台机器上配置 `vibex-server`，或在本机 WSL2 里运行它（测试版）。 |

桌面工作台、移动端和 TUI 都是**客户端**。桌面端默认使用自己的内嵌运行时；你也可以把它切换成连接某个远程运行时，此时它和手机、TUI 一样只是客户端。切换入口在标题栏的 **运行时** 按钮。

## 项目（project）

**项目**是你在 Vibex 里注册的一个文件夹：有名字、有图标、在侧栏里长期存在。侧栏的 **项目** 列表就是它，右键菜单里有改名、定制图标、新建文件夹、导入会话和删除等操作。

一个项目下面可以有**多个工作区**。

## 工作区（workspace）

**工作区**是“以某种方式使用这个项目”。目前有三种位置：

| 模式 | UI 上的叫法 | 行为 |
| --- | --- | --- |
| `CurrentCheckout` | **本地** / 当前检出 | 直接在主检出目录上工作。 |
| `VibexWorktree` | **Worktree** | Vibex 创建一个托管 Git worktree，把改动隔离在独立目录里。 |
| 临时 | **临时会话** | 不属于任何项目，适合一次性任务；不能创建 Worktree。 |

同一个项目下可以同时存在一个 `Local` 工作区和多个 `Worktree` 工作区。这就是为什么可以一边在主分支上干活，一边让 Agent 在隔离目录里试另一个方案。

会话总是属于某一个具体的工作区（或临时空间）。切换工作区不会把未提交改动带过去。

详见[项目与工作区](/workspaces)。

## 会话（session）

**会话**是一次开发任务的完整记录：你的输入、Agent 的输出、工具调用、审批和错误，按时间顺序保存为**时间线**。会话归属于它创建时所在的工作区。

侧栏的 **新建会话** 创建新会话。会话可以重命名、置顶、分叉、归档、批量删除，也可以从其它 Agent 的历史里导入。多个会话可以组成**会话组**，在同一 Worktree 下分屏查看。

会话里的委派会产生**子会话**，它们挂在父会话的所有权树下，有独立时间线。详见[Agent 会话](/sessions)。

## Agent 与供应商

这几个概念经常被混在一起：

| 概念 | 回答的问题 | 在哪里配置 |
| --- | --- | --- |
| **Agent** | 谁来做？ | 配置中心 → Agent |
| **模型供应商配置** | 这个 Agent 用哪个地址、凭据、模型和思考档位？ | 配置中心 → Agent → 详情 |
| **共享供应商（Provider）** | 一套地址、Key 和模型，能被哪些 Agent 和路由组使用？ | 配置中心 → 供应商 |
| **路由组** | 多个 Provider 或模型如何排序、失败转移？ | 配置中心 → 供应商 → 路由组 |
| **本地网关** | 路由组请求实际发往哪个回环端点？ | 配置中心 → 供应商 → 网关 |

一个 Agent 可以只用自己的模型供应商配置，也可以绑定共享 Provider 或路由组。切换只影响后续运行，已有时间线保留原来的运行身份。

详见[Agent 与供应商配置](/agents-and-providers)和[供应商、路由组与本地网关](/providers-and-gateway)。

## 作用域

部分资源可以设定作用范围。可用取值通常是 **global**、**user**、**project** 或 **workspace**，范围越小越不容易误伤其它项目。MCP 服务器当前只提供 **用户** 和 **工作区** 两种。

## 通道（channel）

发布通道决定产品身份和数据目录：**预览**、**RC**、**Stable**。三者可以并存安装，各自使用独立的数据库，互不影响。通道由安装包决定，不能在应用内切换。

## 配对（pairing）

**配对**是给一台设备授予访问某个权威运行时的权限。两种常见路径：

- **桌面 → 手机 / TUI**：桌面端生成二维码或链接，手机扫码、TUI 用 `vibex connect` 认领。
- **服务器 → 桌面 / 手机 / TUI**：`vibex-server` 打印一次性配对码和连接串，客户端填入。

配对时选择的**权限级别**决定该设备能做什么：`read_only`、`approve_only`、`full_control`。级别在发起端决定，客户端无法自行提权。

详见[远程访问与移动端](/remote-mobile)。
