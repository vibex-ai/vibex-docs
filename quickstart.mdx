---
title: "快速开始"
description: "安装 Vibex，连上一个 Agent，完成第一次会话。"
---

这篇指南带你安装桌面端、添加一个 Agent、打开项目目录，然后让 Agent 完成一个可检查的小任务。首次尝试建议使用一个可丢弃的 Git 仓库。

## 1. 安装桌面端

从 [GitHub Releases](https://github.com/vibex-ai/vibex/releases/latest) 下载与你平台匹配的安装包并安装。完整说明和各平台注意事项见[安装](/install)。

<Note>
  macOS 和 Windows 的安装包目前没有代码签名，首次打开会被 Gatekeeper 或 SmartScreen 拦一下。放行方法见[安装](/install)。
</Note>

## 2. 添加一个 Agent

第一次启动时，Vibex 会显示 **开始新的工作** 页面。没有可用 Agent 时会提示 **尚未添加 Agent，请进入配置中心添加。**，点击 **添加 Agent** 进入配置中心。

1. 在 **Agent** 标签页的列表中找到你想用的 Agent。内置预设包括 **Claude Code**、**Codex**、**ZCode** 和 **OpenCode**，另有十多个 ACP 集成。
2. 点击条目右侧的 **+** 把它加入。加入后条目会显示启用开关。
3. 如果该 Agent 由 Vibex 托管且尚未安装，安装卡片会显示 **安装**。点击后 Vibex 会下载并校验运行时；安装过程中不能取消，装好后按钮变为 **检查更新**。
4. 如果条目显示 **由用户管理**，说明它不在托管目录里，Vibex 会直接使用你 `PATH` 上的同名命令行程序——你需要先自己装好它。

接着展开详情页里的 **原生凭证** 卡片完成登录（`Sign in` / `Open sign-in terminal`），或在 **模型供应商配置** 卡片里添加一套自己的地址、Key 和模型。

<Note>
  一个 Agent 可以有多套模型供应商配置；共享 Provider 和路由组在 **配置中心 → 供应商** 里，见[供应商、路由组与本地网关](/providers-and-gateway)。
</Note>

## 3. 打开一个项目目录

1. 在侧栏点击 **新建项目**，或使用 **新建会话** 页面上的 **项目目录**。
2. 在弹出的目录浏览器里选择仓库根目录，确认。
3. 首次尝试请使用测试分支或临时仓库——Agent 会真实修改磁盘上的文件。

也可以选择 **临时会话**，不绑定项目，先试一条提示词。

## 4. 完成第一次会话

1. 在输入框顶部选择 Agent、供应商配置、模型和**思考深度**。
2. 输入一个范围明确的任务，例如“在 `README.md` 中补充安装步骤，并先展示计划”。
3. 查看时间线中的计划和工具调用。需要文件、终端或权限时，Vibex 会显示具体请求，你可以 **允许** 或 **拒绝**。
4. Agent 完成后打开 **Git** 面板检查 **变更**，逐处确认改动，再决定是否提交或继续追问。

<Tip>
  第一次任务先要求 Agent 给出计划，再允许它修改文件。这样你能在时间线里确认范围和风险。
</Tip>

<Warning>
  **停止** 只停止运行，不会回滚已经写入的文件或已经执行的命令。停止后请在 Git diff 和终端里分别确认结果。
</Warning>

## 了解输入框

在输入框中可以组合多种上下文：

| 写法 | 作用 |
| --- | --- |
| `/` | 选择可用的 Prompt 或 slash command。 |
| `@` | 从当前项目引用文件或目录，或引用一个 Agent 委派。 |
| `$` | 插入已启用的 Skill。 |
| 附件按钮 | 添加图片等会话附件。 |

发送前可以选择 Agent、供应商配置、模型、思考深度、对话模式和本会话可用的内置工具。不同 Agent 支持的选项不同，界面会根据运行时探测结果显示可用项。

运行中发送的消息会进入队列。可以编辑、删除、引导运行中的回合，或给消息选一个整点稍后发送。

## 5. 试试终端客户端

TUI 随桌面安装包一起发布。在项目目录里运行：

```bash
vibex
```

它会附着到同一个运行时；`vibex status` 可以查看它会用哪个运行时。详见 [Vibex TUI](/tui)。
