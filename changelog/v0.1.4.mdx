## 亮点

* **Linux 新增 RPM 包** — x86_64 与 aarch64 在 `.deb` 和 AppImage 之外提供 `.rpm`，从已审核的 `.deb` 载荷重新打包，更新清单把它登记为 `rpm/system_installer` 产物。
* **共享 Provider 的改动送达每个 Agent** — 在 Providers 页面编辑一个 Provider 会更新所有绑定到它的 Agent，而不再只更新最初派生该记录的那一个。
* **Codex 读取你声明的模型能力** — 带声明的思考档位或上下文窗口的别名模型会投影进一份私有 Codex 目录，因此档位可选、声明的窗口生效。
* **WSL 运行时配置显示进度** — 添加 WSL 运行时会报告每一步，并把连接连同实时状态保留在 **远程连接** 下。
* **远程 Markdown 图片可以加载** — 会话与渲染文档里的 `http(s)` 图片改走应用自己的 HTTP 客户端，每个响应上限 32 MiB，不再被平台拒绝请求的客户端变成空白。
* **串流的观看成本更低** — 回答流式输出时，桌面端合并只与串流有关的时间线事件，并把侧栏与标签扫掠限制在 30fps 预算内。
* **移动端会话同步更轻** — 手机只在打开图片时拉取附件字节，推理更新只携带新增的增量。

## 新功能

**Linux 打包**

* `.rpm` 由 `scripts/build-rpm.mjs` 从已审核的 `.deb` 数据载荷驱动 `rpmbuild` 生成，安装文件、权限和内嵌的 PDFium 运行时与 `.deb` 逐字节一致。
* 打标签的发布任务上传 RPM，发布页列出下载，签名更新清单携带 `rpm/system_installer`。

**桌面端**

* 后台更新检查不再自行打开标题栏面板；更新仍通过标题栏入口出现，面板点击才展开，并画在树内层，让对话框显示在它上方。
* 选择 **连接 WSL** 会逐步报告发行版检查、下载、安装、启动、转发、配对和连接，关闭对话框后继续运行；失败的尝试可以在 **远程连接** 里重试或查看。
* 远程 `http(s)` Markdown 图片与 HTML `<img>` 源通过应用 HTTP 客户端加载，带连接与请求超时、最多十次重定向和 32 MiB 响应上限。
* 渲染 Markdown 的目标在解析为 URL 前先分类：`file:` URL 或 `C:\work\notes.md` 这样的盘符路径按本地文件解析并打开，`http(s)` 仍是网页，其它协议不支持。
* 标题微光、只与串流有关的时间线批次、侧栏与分组标签扫掠都遵守 30fps 动画预算；减少动效或窗口不活跃时仍渲染静态内容。

**Provider 与 Agent**

* 在 Providers 页面新增或编辑模型会同步到每个 Agent 的启动行与运行时配置，每个 Agent 仍只显示自己声明的协议；删除模型留在 Providers 页面，保存 Agent 页面不再移除其它 Agent 仍能访问的模型。
* 网关路由组与远程调度写入也会重新发布目录，因此 Provider 编辑、删除或 Key 变更会刷新所有受影响的 Agent，包括来自已配对设备的写入。
* Codex 的别名模型会写入 Profile 旁的 `vibex-models.json`，列出每个启用模型及其声明的上下文窗口和思考档位，并把 `model_catalog_json` 指向它；两者都未声明的 Profile 保持原输出。
* 托管 Agent 的安装或回滚只有在快照与新的启动指纹匹配时才算当前，避免新会话以 `runtime_switch_configuration_unavailable` 失败。
* pi-acp 的 `<provider>/<model>` 模型 id 会带上 provider 命名空间，读回时再剥掉，因此含斜杠的产品 id 不再被拒绝为 `Model not found`。

**移动端与远程**

* 时间线读取用有界标记替换内联附件，只在图片打开时读取详情项；`agent_session` 事件限定在打开的会话，应用在后台时只发通知，缺口用有界追页恢复。
* 推理分块按增量发送，内联附件字节从时间线页预算中扣除。
* 远程时间线页限制在 512 KiB，为 Relay 的 E2EE 信封留出余量；Relay 的帧上限通过 `VIBEX_RELAY_MAX_WEBSOCKET_FRAME_BYTES`（默认 2 MiB）暴露。

**技能与市场**

* 安装按钮在 Skill 文件夹抓取和预览期间保持可用，大 Skill 上的按下会被记住，并在预览到达时立刻开始安装；写入的字节仍严格等于预览披露的内容。
