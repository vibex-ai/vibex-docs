Vibex 使用 [Agent Client Protocol](https://agentclientprotocol.com/)（ACP）連接線上 Agent。**Agent**（由誰執行）和**模型供應商設定**（使用哪個模型、走哪條線路）是分開管理的兩件事。

這兩者都在 **Config Center → Agent** 分頁中操作。

## Agent 分頁的結構

開啟 **Config Center → Agent** 後，左側是 Agent 清單，右側是所選 Agent 的詳細資料區。詳細資料區由上到下有三張卡片：

| 卡片 | 作用 |
| --- | --- |
| **Agent installation** | 檢視安裝狀態，安裝 / 升級 / 解除安裝受管執行環境。 |
| **Native credentials** | 登入 Agent 自己的帳號。 |
| **Model provider configuration** | 為該 Agent 設定模型供應商、模型和憑據。 |

<Note>
  模型供應商**不是**獨立分頁。它掛在每個 Agent 底下，因為不同 Agent 支援不同的通訊協定和模型目錄。
</Note>

## 新增 Agent

左側清單依狀態分組，每個條目右側可執行的動作取決於目前狀態：

| 狀態 | 可做的操作 |
| --- | --- |
| **Not added** | 點選 **+** 加入。 |
| **Not installed** | 點選 **Install**，Vibex 會下載並驗證受管執行環境。 |
| **Update available** | 點選 **Upgrade** 升級至新版本。 |
| **Available** | 已就緒，可用啟用開關控制它是否出現在會話的 Agent 選擇器中。 |
| **Managed by user** | 該 Agent 不在受管目錄中，Vibex 會使用你 `PATH` 上的命令列程式。 |
| **Disabled** | 已停用。 |

Vibex 內建四個預設：**Claude Code**、**Codex**、**ZCode**、**OpenCode**。ACP 目錄另外提供 **Google Antigravity**、**Cline**、**Codebuddy Code**、**GitHub Copilot**、**Cursor**、**DeepSeek Harness**、**Devin CLI**、**Gemini CLI**、**Grok**、**Hermes**、**Kimi Code CLI**、**Pi** 等整合。

<Warning>
  **Install** 會從網路下載並驗證執行環境，過程中無法取消。**Uninstall** 會顯示確認對話方塊，並刪除該 Agent 的受管執行環境和快取版本；會話歷程會保留。
</Warning>

### 新增自訂 ACP Agent

點選清單底部的 **Add custom ACP Agent**，填寫：

| 欄位 | 說明 |
| --- | --- |
| **Agent ID** | 小寫 kebab-case 識別碼，例如 `my-acp-agent`。 |
| **Display name** | 顯示名稱。 |
| **Description** | 選填，說明用途。 |
| **ACP command** | 可執行檔、`npx` 或 `uvx` 形式的命令。 |
| **Arguments** | 以空格分隔的參數。 |
| **Environment variables** | 每行一個 `KEY=value`。 |

自訂 Agent 目前只能新增，不能編輯；關閉開關會刪除它，但會話歷程會保留。

## 登入 Agent 帳號

**Native credentials** 卡片管理 Agent 自己的帳號，它與外部 CLI 共用同一份憑據——卡片上會明確寫出 "Agent-native account · shared with the external Agent CLI"。

- 可用的登入方式由 Agent 決定，常見的有 **Sign in**、**Save and sign in**、**Open sign-in terminal**。
- 卡片提供 **Refresh methods**、**Verify account**、**Refresh models**、**Re-authenticate**、**Sign out**。
- 重新驗證會影響正在使用舊憑據的 Agent 處理程序；介面會先顯示提示。
- **Sign out** 會同時影響外部 CLI 和 Vibex 會話，執行前會顯示受影響的會話數量。

## 設定模型供應商

在 **Model provider configuration** 卡片中點選 **Add config**，或對現有設定點選編輯。編輯器分為三個區段：

### Basics

| 欄位 | 說明 |
| --- | --- |
| **Provider name** | 必填。顯示用名稱。 |
| **Note** | 選填備註。 |
| **Website URL** | 選填。 |

### Connection & credentials

| 欄位 | 說明 |
| --- | --- |
| 憑據 | 由所選 Agent 決定使用 API Key、OAuth 還是 Agent 帳號。 |
| **Default API request URL** | 供應商的 API 位址，例如 `https://provider.example/v1`。部分 Agent 會鎖定此項。 |
| **Set an address per protocol** | 摺疊區，需要為不同通訊協定分別指定位址時展開。 |

API Key 輸入框是**唯寫**的：已儲存時顯示 "Saved"，留空則保留原值；要取代就輸入新值，要清除則點選 **Clear**。

### Models

Vibex **不會預先建立模型清單**，需要你手動新增或從供應商擷取：

- **Model ID** —— 手動輸入模型識別碼，例如 `deepseek-chat`。
- **Fetch models** —— 需要已填寫 API Key 和位址，會傳回該帳號可用的模型。
- **Model API protocol** —— 每個模型可以個別指定通訊協定，預設繼承供應商設定。
- **Reasoning** —— 選擇是否進行推理，或指定**思考深度**等級。
- **Context window / Max output tokens** —— 在 Advanced 摺疊區中宣告模型上限。

思考深度的可選等級來自供應商或 Agent 的宣告，常見取值為 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。

## 在會話中使用

傳送訊息前，從 Composer 頂部的階層式選單選擇 **Agent**、**Model provider**、**Model** 和 **Thinking depth**。切換只會影響後續執行；既有時間線會保留原次執行的 Agent 和模型資訊。

<Warning>
  **Test connection** 和 **Fetch models** 會實際連線至供應方網路，並可能消耗額度。行動端的 `read_only` 裝置無法觸發這些操作。
</Warning>

## 疑難排解

- **Agent 不在清單中**：確認可執行檔在 `PATH` 中，或檢查自訂命令和參數。
- **模型無法選取**：先執行 **Refresh models**，再檢查該模型是否已啟用。
- **驗證失敗**：確認帳號狀態，重新登入；不要在 Issue 中貼上回應標頭或 token。
- **遠端看不到設定**：確認裝置權限等級是否為 `full_control`，以及目前連線的是哪個權威執行環境。
- **受管 Agent 安裝失敗**：檢查網路是否能連線至 GitHub 與 nodejs.org，然後重試。
