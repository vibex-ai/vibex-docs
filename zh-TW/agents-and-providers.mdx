Vibex 使用 [Agent Client Protocol](https://agentclientprotocol.com/)（ACP）連接線上 Agent。**Agent**（由誰執行）和**模型供應商設定**（使用哪個模型、走哪條線路）是分開管理的兩件事。

這兩者都在 **配置中心 → Agent** 分頁中操作。

## Agent 分頁的結構

開啟 **配置中心 → Agent** 後，左側是 Agent 清單，右側是所選 Agent 的詳細資料區。詳細資料區由上到下有三張卡片：

| 卡片 | 作用 |
| --- | --- |
| **Agent 安裝** | 檢視安裝狀態，安裝 / 升級 / 解除安裝受管執行環境。 |
| **原生憑證** | 登入 Agent 自己的帳號。 |
| **模型供應商配置** | 為該 Agent 設定模型供應商、模型和憑據。 |

<Note>
  模型供應商**不是**獨立分頁。它掛在每個 Agent 底下，因為不同 Agent 支援不同的通訊協定和模型目錄。
</Note>

## 新增 Agent

左側清單依狀態分組，每個條目右側可執行的動作取決於目前狀態：

| 狀態 | 可做的操作 |
| --- | --- |
| **未新增** | 點選 **+** 加入。 |
| **未安裝** | 點選 **安裝**，Vibex 會下載並驗證受管執行環境。 |
| **有可用更新** | 點選 **升級** 升級至新版本。 |
| **可用** | 已就緒，可用啟用開關控制它是否出現在會話的 Agent 選擇器中。 |
| **由使用者管理** | 該 Agent 不在受管目錄中，Vibex 會使用你 `PATH` 上的命令列程式。 |
| **已停用** | 已停用。 |

Vibex 內建四個預設：**Claude Code**、**Codex**、**ZCode**、**OpenCode**。ACP 目錄另外提供 **Google Antigravity**、**Cline**、**Codebuddy Code**、**GitHub Copilot**、**Cursor**、**DeepSeek Harness**、**Devin CLI**、**Gemini CLI**、**Grok**、**Hermes**、**Kimi Code CLI**、**Pi** 等整合。

<Warning>
  **安裝** 會從網路下載並驗證執行環境，過程中無法取消。**解除安裝** 會顯示確認對話方塊，並刪除該 Agent 的受管執行環境和快取版本；會話歷程會保留。
</Warning>

### 新增自訂 ACP Agent

點選清單底部的 **新增自訂 ACP Agent**，填寫：

| 欄位 | 說明 |
| --- | --- |
| **Agent ID** | 小寫 kebab-case 識別碼，例如 `my-acp-agent`。 |
| **顯示名稱** | 顯示名稱。 |
| **描述** | 選填，說明用途。 |
| **ACP 命令** | 可執行檔、`npx` 或 `uvx` 形式的命令。 |
| **參數** | 以空格分隔的參數。 |
| **環境變數（選填）** | 每行一個 `KEY=value`。 |

自訂 Agent 目前只能新增，不能編輯；關閉開關會刪除它，但會話歷程會保留。

## 登入 Agent 帳號

**原生憑證** 卡片管理 Agent 自己的帳號，它與外部 CLI 共用同一份憑據——卡片上會明確寫出 "Agent-native account · shared with the external Agent CLI"。

- 可用的登入方式由 Agent 決定，常見的有 **登入**、**儲存並登入**、**開啟登入終端**。
- 卡片提供 **重新整理驗證方式**、**驗證帳號**、**重新整理模型**、**重新驗證**、**登出**。
- 重新驗證會影響正在使用舊憑據的 Agent 處理程序；介面會先顯示提示。
- **登出** 會同時影響外部 CLI 和 Vibex 會話，執行前會顯示受影響的會話數量。

## 設定模型供應商

在 **模型供應商配置** 卡片中點選 **新增配置**，或對現有設定點選編輯。編輯器分為三個區段：

### 基本資訊

| 欄位 | 說明 |
| --- | --- |
| **供應商名稱** | 必填。顯示用名稱。 |
| **備註** | 選填備註。 |
| **官網連結** | 選填。 |

### 連線與憑證

| 欄位 | 說明 |
| --- | --- |
| 憑據 | 由所選 Agent 決定使用 API Key、OAuth 還是 Agent 帳號。 |
| **預設 API 請求位址** | 供應商的 API 位址，例如 `https://provider.example/v1`。部分 Agent 會鎖定此項。 |
| **按協定分別設定位址** | 摺疊區，需要為不同通訊協定分別指定位址時展開。 |

API Key 輸入框是**唯寫**的：預設以遮罩顯示，點眼睛圖示可以顯示明文；已儲存時會標出 **已儲存**。沒有改動過的欄位不會改寫已儲存的值，留空儲存會保留原值；要清除就點 **清除**，此時狀態變成 **儲存後清除**，按鈕變成 **保留密鑰**。

### 模型

編輯器把模型分成兩欄：左欄是 **可選模型** 選擇器，右欄是所選模型的 **模型設定**。選擇器是唯一的模型清單——點選一列，右欄就顯示它的可編輯欄位，而不是把清單再重複一遍。

Vibex **不會預先建立模型清單**：

- **擷取模型** —— 需要已填寫 API Key 和位址，擷取該帳號可用的模型來填充 **可選模型**。擷取本身不寫入任何設定。
- **可選模型** —— 勾選一列會把這個模型加入草稿；取消勾選會移除它但保留已宣告的能力，重新勾選即可還原。**全選** / **全部啟用** 可以批次處理；沒有可擷取的模型時，在 **自訂模型** 裡手動輸入 id 再加入。
- **Model ID** / **顯示名稱** —— 在右欄編輯。選取狀態按模型 id 追蹤，所以重新命名之後右欄仍停在正在編輯的模型上。
- **模型介面協定** —— 每個模型可以個別指定通訊協定，預設 **繼承**（繼承供應商設定）。
- **推理能力** / **思考檔位** —— 選擇是否進行推理，或宣告**思考深度**等級。
- **上下文視窗 / 最大輸出 Token** —— 在 **進階** 摺疊區中宣告模型上限。

供應商不提供的模型，右欄會顯示 **新增該模型**，點它把該模型加入清單。

思考深度的可選等級來自供應商或 Agent 的宣告，常見取值為 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。

## 在會話中使用

傳送訊息前，從輸入框頂部的階層式選單選擇 **Agent**、**模型供應商**、**模型** 和 **思考深度**。切換只會影響後續執行；既有時間線會保留原次執行的 Agent 和模型資訊。

<Warning>
  **測試連線** 和 **擷取模型** 會實際連線至供應方網路，並可能消耗額度。行動端的 `read_only` 裝置無法觸發這些操作。
</Warning>

## 疑難排解

- **Agent 不在清單中**：確認可執行檔在 `PATH` 中，或檢查自訂命令和參數。
- **模型無法選取**：先執行 **重新整理模型**，再檢查該模型是否已啟用。
- **驗證失敗**：確認帳號狀態，重新登入；不要在 Issue 中貼上回應標頭或 token。
- **遠端看不到設定**：確認裝置權限等級是否為 `full_control`，以及目前連線的是哪個權威執行環境。
- **受管 Agent 安裝失敗**：檢查網路是否能連線至 GitHub 與 nodejs.org，然後重試。
