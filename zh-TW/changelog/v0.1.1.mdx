## 亮點

* **一次新增多臺遠端主機** — 連續新增 SSH 主機會逐臺完成配置：每個請求排隊等待，不再取消已經在下載的任務；無法連線的主機也不會卡住後面的佇列。
* **`vibex-bin` 進入 AUR** — 穩定版釋出把標籤交給 AUR 任務，Arch 使用者可以用 `paru -S vibex-bin` 或 `yay -S vibex-bin` 安裝已稽核的 Linux 包，不必手動解包 `.deb`。
* **Windows 上帶標籤的視窗** — 工作列按鈕顯示 “Vibex” 而不是一個裸圖示，shell 與遠端主機通訊時也不再閃出控制台視窗。
* **遠端主機保持連線，連不上時說明原因** — 配置執行在工作臺執行環境上，SSH 連線成功後立刻開啟的會話不會在第一次讀取時因 socket 關閉而失敗。`wsl.exe` 失敗會報告自己的訊息，掛起的 WSL 讀取在 15 秒後放棄，認證失敗會帶上伺服器實際返回的內容。
* **標註跟得上游標** — 框、線、箭頭、畫筆和馬賽克筆畫在 4K 截圖上不再中途閃沒或卡住視窗，撤銷歷史同時按位元組數和條目數設限。
* **Providers → Models 標籤頁保持可讀** — 行改為實測佈局，開啟的行內編輯器會把下面的行推開，而不是讓名稱和開關畫進它的欄位裡。

## 新功能

**遠端執行環境**

* 配置是一個佇列：第二臺主機不會替換第一臺已經啟動的任務，也不會留下 `.part` 檔案並讓行停在 **離線 / 未安裝**。
* 配置失敗——主機不可達、執行環境配置不可用、任務被停止——以頂層提示到達。WSL 對話框提交後會關閉，此前錯誤被寫進已經消失的主體。
* 停滯的產物下載在靜默一分鐘後就失敗，而不是把執行掛滿五分鐘；連線有自己的 30 秒預算，只要還在收到位元組，流可以按需持續。
* 每個 SSH、`ssh-keygen` 和 `wsl.exe` 子程序都隱藏啟動，Windows 不再為連線、隧道和主機金鑰探測各開一個控制台視窗。
* 遠端執行環境借用工作臺的程序級 Tokio 執行環境，而不是自建一個並隨配置 worker 丟棄；後端不再比它的 reactor 活得更久，連線成功後緊接著的目錄讀取也不會報 `remote_socket_write_failed`。
* 列出 WSL 發行版時同時排空兩個管道並設 15 秒期限，區分啟動失敗、非零退出（帶 stderr 和退出碼）與超時，讀取移出 UI 執行緒；對話框把讀取中、失敗重試和發行版列表畫成獨立狀態。
* WSL 錯誤按 WSL 診斷：每個 `wsl_*` 錯誤碼不再歸類為未知、也不再給一個沒有 SSH 跳板的傳輸顯示“安裝 SSH 伺服器”，而是指向 `wsl --update` 與 `wsl -l -v`。
* 認證失敗攜帶伺服器 stderr，鎖住的金鑰、空的 agent 和錯誤的 `IdentityFile` 不再都讀作同一句 “SSH authentication failed”。

**桌面端**

* 工作臺、托盤恢復的視窗和電腦操控面板按釋出通道的產品名命名，工作列按鈕和視窗切換器因此有標籤。
* 截圖標註改為從一張工作圖繪製，而不是每次指標取樣都編碼一次 PNG。一筆現在就地擴充套件工作圖，形狀在筆畫基線上重畫，每幀最多上傳一次，退休的紋理在繪製它的那一幀之後釋放。
* Providers → Models 標籤頁用 GPUI 的實測列表放置行；開啟或關閉編輯器會重新測量，列表擁有捲軸槽，卡片滾動自己的行而不是讓頁面滾動卡片。

**嵌入式瀏覽器**

* Windows 建構從啟動器旁按版本命名的目錄讀取 Chromium 版本，不啟動程序，因此傳送 `Chrome/<version>` 而不是 `HeadlessChrome`，機器人檢查返回正常頁面而不是挑戰頁。

**打包與釋出**

* 穩定版 GitHub Release 會派發 AUR 工作流並傳入標籤；派發結果只報告而不致命，釋出不會因此失敗。
* AUR 任務在第一次 `makepkg` 前把 PKGBUILD 樹和 `SRCDEST` 交給非特權 `builder` 帳戶。
* 質量門恢復：格式檢查按位元組比較，macOS clippy 任務不再被 Windows 專用助手卡住，MCP 金鑰測試不再訪問真實鑰匙串。
* 許可證門忽略 Gradle 建構樹，本地 Android 建構複製到 `app/build/` 的 emoji 字型不再讓 `pnpm check:licenses` 失敗。

**效能**

* 嵌入式瀏覽器不再啟動 Chromium 程序來獲知版本，讀取建構目錄是瞬時的，也不會在每次執行環境啟動時留下多餘視窗。
* 標記 4K 截圖不再每次指標移動都做約 100 毫秒的 UI 執行緒編碼工作。
* 列出 WSL 發行版不再佔用 UI 執行緒，半安裝的 WSL、停掉的 `LxssManager` 或 AppLocker 提示不會再凍住設定視窗。
