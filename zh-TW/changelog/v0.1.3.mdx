## 亮點

* **Windows 安裝包不再替換過長的使用者 `Path`** — 安裝程式現在通過一個小助手讀取登錄檔值的真實長度、保留它的型別，讀取失敗時不寫入。此前超過 1023 個字元的 `Path` 會被讀成空字串，安裝目錄寫入後其它條目全部丟失。
* **配對以內建 Relay 為首選** — 配對對話框把無需填寫地址的內建中繼排在首位，區域網與 Tailscale 緊隨其後，直連 HTTPS 和自託管 Relay 收進 **其它方式**。
* **本地頁面在嵌入式瀏覽器中開啟** — 雙擊 HTML 檔案會用樣式表、指令碼和圖片完整預覽頁面，由限定在該檔案目錄內的迴環源提供。
* **SSH 執行環境乾淨重連** — 切回已停靠的執行個體會複用仍存活的隧道，而不是再開一個 `ssh -L`；重建的隧道會一直探測到真正就緒。
* **每個執行環境 home 只有一個視窗** — 再次開啟 Vibex 會讓正在執行的視窗來到前臺並退出，不再開啟第二個視窗、落到 `desktop_runtime_home_locked`。

## 新功能

**遠端訪問與 Relay**

* 內建 Relay 是配對的第一個選項，也是唯一不需要輸入的選項。官方源位於 `vibex-core` 中且從不渲染，因此不會被打錯或誤認為可配置端點；只有執行環境真正提供該源時，入口才報告中繼線上。
* 桌面端的 Relay 行、移動端選擇器和 TUI 路由只顯示連線名稱，不再列印讀者無法修改的地址。
* Relay 把 WebSocket 握手和房間註冊計入客戶端地址：迴環反向代理後取最右側的 `X-Forwarded-For`，否則取對端地址；跟蹤表有界並在兩個空閒視窗後清理，`/api/info` 報告生效的上限。

**桌面端**

* 設定導航在視窗較矮時只讓分組列表在固定搜尋框下滾動，每個分割槽仍然可達；重新開啟設定會回到頂部，不再恢復上次的滾動位置。
* 檔案樹、檔案搜尋和 **開啟方式 → 嵌入式瀏覽器** 都把本地頁面開在面板裡，渲染文件或會話中的網頁連結也一樣。每個目錄有一個帶獨立令牌的迴環伺服器，拒絕路徑穿越、點檔案、反斜槓和指向目錄外的符號連結，最後一個標籤關閉時伺服器停止。
* Agent 預覽仍保持原有邊界：`browser_preview_open` 依然需要一次性批准，只提供一個已批准的檔案，批准一個檔案不會暴露它的目錄。
* 每個執行環境 home 的鎖和啟用端點彼此獨立，預覽版、RC 版和穩定版安裝不會互相爭搶。

**技能與市場**

* 從整倉庫源安裝 Skill 不再在舊的 16 MiB 包上限處失敗：下載上限提高到 128 MiB，檔案數上限 16384，解壓後大小上限 64 MiB，解壓上限仍限制解壓炸彈。
* 超過下載上限的倉庫會報告自己的錯誤碼和倉庫名，不再在無關的搜尋框下顯示目錄通用的 `market_response_too_large`。

**Windows 安裝包**

* 安裝程式和解除安裝程式把 `Path` 編輯交給 `vibex-installer-env.exe`：它向登錄檔詢問精確位元組長度、讀取完整值、按整項大小寫不敏感匹配、保留 `REG_SZ` 與 `REG_EXPAND_SZ`，讀取失敗時不寫入。
* 解除安裝程式只移除指向安裝目錄的條目。**如果更早的版本已經替換過你的使用者 `Path`，本次更新無法重建丟失的條目**，需要從備份恢復或手動重新新增。
