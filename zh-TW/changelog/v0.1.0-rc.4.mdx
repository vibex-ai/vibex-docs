## 亮點

* **內建十套主題，明暗分開選擇** — 外觀不再只是一個淺色／深色開關。桌面端內建十套配色：淺色為 Vibex Light、Catppuccin Latte、Gruvbox Light、Solarized Light、GitHub Light，深色為 Vibex Dark、Catppuccin Mocha、Gruvbox Dark、Tokyo Night、Nord。淺色與深色各自獨立選擇，任意淺色都能搭配任意深色；你也可以把 JSON 主題檔案放進執行環境 home 目錄的 `themes` 資料夾來擴充清單，檔案裡沒寫的顏色會按它實際所在的背景補齊。所有內建主題的正文與次要文字對比度都不低於 4.5:1（`04d582d`）。
* **視窗邊框跟隨你的系統** — 標題列改為 38 像素浮層浮在介面之上，不再單獨佔一條，因此側欄和各個面板一直延伸到視窗頂邊，右側欄也整體畫成一塊。標題列按鈕與你所在的平台一致：macOS 保留紅黃綠交通燈，Windows 保留貼靠佈局需要的區域，Linux 跟隨 GTK 的裝飾佈局。視窗做不到的按鈕不再顯示，按按鈕也不會誤觸發視窗拖曳（`5a2f015`、`a72bf55`、`4035d0e`、`dd87a6f`、`18c8628`）。
* **執行環境集中在一個管理器裡** — 桌面端和行動端共用同一個執行環境管理器，用來瀏覽、新增、切換、重新命名和刪除執行環境；清單與所選執行環境的詳情放在同一面板，不再層層彈窗。切走時不再關閉內建執行環境，本機終端和正在執行的 Agent 回合都能保留；位址填錯什麼都不會變，失敗原因會記在對應的執行環境上。清單還會在連線之前就告訴你，對方是另一台 Vibex 桌面端還是無介面的伺服器（`3e72051`、`a33e67c`）。
* **重做的 Agent／模型供應商／模型選擇器** — 在 Composer 裡選模型現在是一個浮動選單：頂部是 Agent 標籤列，有 **Starred models** 檢視，每列都有星號，預設推理檔位有標記，搜尋會把最貼近的結果和你收藏的模型排在前面。同一視窗尺寸下選單高度保持不變，輸入或切換 Agent 時不會在指標底下跳來跳去，搜尋框也更寬了（`973e015`、`6a6380a`）。
* **Agent 靜默失敗時現在會報錯** — Agent 連線可能吞掉內部錯誤（例如 API key 被拒），然後什麼都不回就結束回合：回答憑空消失、沒有任何報錯，訊息卻算作已傳送。現在這種情況會以錯誤結束，並提示可以怎麼處理；真正的停止、權限確認或確實有內容產生的回合不受影響（`dcd01d8`）。
* **搜尋不再拖慢整個應用程式** — 以前開啟會話搜尋會為每個會話重建索引，而且對話框開著的時候每一幀都重跑整個掃描，繁忙會話會從約 58 fps 掉到 6-8 fps。現在索引只建一次並保持可用，掃描放到背景，再次開啟對話框是瞬間完成的（`95d0a8a`）。
* **終端保持流暢** — 終端以前每次重繪都要把每個儲存格重新構造成一個物件，而輸出每一行、游標每閃一次都會重繪，所以連閒置終端都可能每秒卡住視窗兩次。現在整個網格一次畫完：同一幀在 debug 建置下從約 242 ms 降到約 3 ms（`eabe83b`）。
* **Android 安裝包可以正常升級，體積也恢復正常** — 以前每個 Android 安裝包的內部版本號都一樣，凡是會檢查版本的通道，新 APK 都裝不上舊版本。現在版本號由發佈版本推導，`0.1.0-rc.4` 排在 `0.1.0-rc.3` 之後；無法編碼的版本會讓建置直接失敗，而不是悄悄沿用舊號。發佈建置還會先清掉早先 debug 建置殘留的函式庫：曾漲到 429 MB 的安裝包回到約 73 MB（`cb9809f`、`8de5d4e`）。
* **不再內建編輯器原始碼** — Vibex 過去為了建置介面工具包，要隨倉庫帶上一份 95 MB 的 Zed 編輯器原始碼。這份副本已經移除，工具包改為使用正常發佈的軟體套件，程式碼檢出小了很多，建置也更容易重現。唯一看得見的變化是：依賴這份副本的**毛玻璃**（Frosted glass）效果已隨之下線（`6ffcf7c`、`825bb97`、`9ecc107`）。

## 新功能

**執行環境與遠端**

* 桌面端和行動端都能在同一個視窗裡瀏覽、新增、切換、重新命名和刪除執行環境，清單與所選執行環境的詳情同處一個面板（`3e72051`）
* 切走時保持內建執行環境繼續執行；先連線成功再切換，位址錯誤則一切照舊；失敗原因隨每個執行環境單獨保留（`3e72051`）
* 執行環境清單標明對方是 Vibex 桌面端還是無介面伺服器，配對時即已知，並在每次連線時重新整理（`a33e67c`）

**主題與外觀**

* 十套內建淺色／深色配色任選並自由搭配；用只寫想改顏色的 JSON 主題檔案擴充清單（`04d582d`）
* 懸停和選取顏色改為取自主題自身的背景，暖色或帶色調的主題不再配到中性灰的高亮（`04d582d`）
* 右側欄（檔案、Git、子 Agent 時間線）現在整體畫成一塊（`18c8628`）

**桌面端**

* 標題列以 38 像素浮層浮在介面之上，每一欄都為它留出空間，內容不會被壓住（`5a2f015`）
* 標題列按鈕遵循各平台自己的規則，在 Linux 上遵循 GTK 的裝飾佈局；視窗做不到的操作不再顯示，按下按鈕也不會誤觸發視窗拖曳（`a72bf55`）
* 用量頁的範圍開關改為滑動切換，控制項描邊更柔和（`37e8029`）
* 用量頁的篩選器歸到範圍開關之後成組排列，每個直接顯示它篩選的值（多選時顯示 `+N`），不用再開啟選單才知道篩了什麼（`2a03753`）
* 模型供應商編輯器改為 Enter 儲存而不關閉對話框，所有欄位都會寫入草稿，錯誤顯示在出問題的欄位下方（`69489d7`）
* MCP 與 Skills 的設定匯出移到各自頁面，不必再繞進主導覽到不了的 Advanced 頁（`f7c3129`）
* 新增 **Developer** 設定分區：**FPS monitor** 開關在工作台上疊加即時幀率、幀耗時與資源佔用（`a80f3fd`），浮層可拖曳並記住位置（`b2aa073`），開啟期間每秒記錄一次取樣到診斷資料（`8a30d6a`）
* Composer 的 Agent／模型供應商／模型選擇器改為真正的浮動選單：Agent 標籤列、**Starred models** 檢視、每一列的星號開關、標出預設推理檔位，並帶開啟／關閉動畫（`973e015`）
* 選擇器搜尋先按開頭符合、再按包含符合、最後按供應商名稱排序，已收藏的模型置頂；收藏可儲存並重排清單；切換進行中鎖定 Agent 列；關閉後焦點回到 Composer（`973e015`）

**Agent 與 ACP**

* zcode 轉接器從 0.17.2 升級到 0.37.1；審批提示現在會顯示工具呼叫的可讀說明和將要改動的檔案，轉接器固定使用 Node 執行（`d88327f`）
* Cursor 現在按模型參數逐個發佈選項，不再把每種參數組合凍結成單獨的模型 id：模型按名稱列出，`fast`、`context` 和推理深度作為所選模型上的選項來設定（`8ab812f`）
* 推理深度在會話中仍可隨時調整；布林型的 thinking 開關歸入會話選項，不再被當成一個深度檔位；用舊變體 id 儲存的模型（例如 `claude-opus-5[thinking=true,context=300k]`）在確認 CLI 已使用新形態後，會自動收斂為模型名（`8ab812f`）

## 修復

**桌面端**

* 補齊此前悄悄缺失的圖示：共 34 個圖示路徑畫不出東西，其中 32 個從未註冊（側欄專案圖示、檔案與資料夾操作、檔案類型圖示、拖曳手柄），另有 2 個指向了錯誤的目錄（`2b37048`）
* 執行環境按鈕現在會顯示自己的圖示，點擊後其面板保持開啟（`de067b9`）
* 配對的手機會始終拿到自己的側欄佈局，而不是桌面端當時正在顯示的遠端執行環境的佈局（`444226b`）
* 摺疊卡片或合併流程列之後，最後一列下方不再留下一條空白帶、讓檢視停在那裡（`3e59958`）
* macOS 的 Dock 圖示大小現在與旁邊的圖示一致，點擊 Dock 圖示也能重新開啟視窗（`a5af0ee`）
* 模型供應商編輯器裡連線欄位排在模型之前，與你填寫時的順序一致（`232e8b6`）
* 用量頁工具列和圖表標題改用標準的小尺寸控制項，不再侷促（`c98f0f4`）
* 模型供應商與模型選單在同一視窗尺寸下保持固定高度，輸入或切換 Agent 時不再改變大小；清單在內部捲動，搜尋框也拿回了寬度（`6a6380a`）
* 切換會話不再讓對話跳動：時間線保留已測量的列高，並記住你正在看的那一輪，向上翻看的讀者會停在原處（`5785cdb`）
* 側欄未選取會話列更易讀，與專案和工作區列保持一致（`fff3271`）

**Agent 與 ACP**

* 完全沒有輸出的回合現在會以錯誤結束，不再儲存一條空回答；等待輸入、被你停止或確實有內容產生的回合不受影響（`dcd01d8`）
* Cline 的位址固定為 `api.openai.com`：該端點由 Agent 自己掌握，設定裡填的位址不再起作用，預覽中會顯示它實際呼叫的位址（`4285157`）

**行動端與建置**

* Android 建置現在會傳入 NDK API 級別，建置、打包和打標籤發佈流程不再在連結環節失敗（`50a03f9`）
* Android 版本號由發佈版本推導，新建置可以覆蓋安裝舊版本；無法編碼的版本、或預發佈序號超過 99 時建置直接失敗（`cb9809f`）
* 發佈建置會先清掉早先 debug 建置殘留的函式庫，安裝包不再夾帶 debug 函式庫（`8de5d4e`）
* 滑開抽屜不再順帶捲動它展開的頁面，滑動之後手指帶起的慣性也不會傳到抽屜清單裡（`2609443`）
* 鍵盤收起後，點擊仍然聚焦的輸入框可以重新喚出鍵盤（Android 與 iOS 均如此）；點擊輸入框旁邊的按鈕不會彈出鍵盤，鍵盤已經在螢幕上時點擊也不會重複喚起（`fe7f843`）

## 效能

* 會話搜尋在對話框關閉後保留索引，掃描放在背景而不是繪製時進行，文字就地符合（`95d0a8a`）
* 終端把整個網格作為單一元素繪製，指標輸入也收斂為單一監聽器（`eabe83b`）

## 內部、建置與文件

* 不再內建 Zed 原始碼：介面工具包改用已發佈的軟體套件，其中一小段未發佈的橋接程式碼移入本倉庫；隨套件字型和行動端圖示遷出舊副本；行動端平台層、鍵盤處理和 iOS 入口都重建在已發佈的軟體套件之上（`6ffcf7c`）
* 介面工具包系列固定到某個具體修訂，並在專案文件（spec）中寫明該固定點何時可以前移（`825bb97`、`9ecc107`、`e1d56bc`）
* 建置與授權檢查適配了新的相依性和資源，重新產生軟體物料清單（SBOM）、第三方聲明與授權策略，並更新發佈打包、平台支援、UI 邊界與授權文件（`6ffcf7c`、`04d582d`、`a5af0ee`）
* 專案文件（spec）更新了視窗邊框、用量工具列、靜默 Agent 回合、相依性來源、終端繪製與 Cursor 參數化模型選擇器相關內容（`2a03753`、`dcd01d8`、`e1d56bc`、`eabe83b`、`8ab812f`）
* 行動端捲動監聽器的一處程式碼檢查失敗不再影響 Rust 品質門檻和 CI（`45709c8`）
* Android 發佈工作不再在建置開始前就中斷：SDK 初始化動作仍在請求 Google 已停止發佈的舊 `tools` 套件，現已固定到去掉該套件的版本（`b870998`）
* 工作區與打包輸入的版本號統一升到 `0.1.0-rc.4`（`4dd6ce6`）
