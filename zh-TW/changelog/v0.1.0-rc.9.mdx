## 亮點

* **本機模型閘道** — 一個回環端點現在擋在所有共享 Provider 前面。它說 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Generative AI 四種協定，在它們之間翻譯，並把每次呼叫轉給服務所請求模型的 Provider。
* **會容錯轉移的路由** — 路由就是一個可選模型。可以用 `(Provider, model)` 組合，從七種策略裡挑一種，某個成員答不出來時閘道自動走到下一個。
* **重建的供應商工作區** — 供應商、路由組和閘道合成一個工作區：可折疊側欄、統一的身份列、原地編輯。手工設定的 Provider 變成可重複使用範本，預設的模型清單改由 `models.dev` 目錄提供。
* **SSH 與 WSL 遠端執行階段** — 桌面端可以把權威執行階段放到另一台機器上：透過 SSH 安裝 `vibex-server`、建立通道、自動配對，並在升級失敗時回滾且保住執行階段身份。
* **自架產物自己發佈** — Linux x86_64/aarch64 與 macOS 的無頭伺服器包在固定版本的 Debian 12 建置器裡產出；穩定版映像同時鏡像到 Docker Hub 和 CNB；AUR 套件重新發佈 Linux `.deb`；Linux 負載體積縮小三分之一。
* **時間線像文件一樣可讀** — 工具呼叫不再是一坨 JSON，而是結構化呈現：路徑與值欄位、待辦清單、以清單呈現的提問，以及以差異呈現的編輯。標頭先講意圖、結果和耗時。
* **終端裡每個畫出來的鍵都是按鈕** — TUI 中 `鍵 標籤` 形式的圖例現在就是控制項：點擊它會按下它寫明的那個鍵，走的是鍵盤同一條分發路徑。
* **又多了十位守衛** — 新建會話首頁的競技場從六場戰鬥擴到十六場，每位守衛都有自己的登場、巡遊節奏和隨從效果。

## 新功能

**本機模型閘道**

* 一個回環端點提供編碼 Agent 已經在用的四種線路協定，並把每個請求轉給服務所請求模型的共享 Provider；協定翻譯走同一套中間表示，包括在串流形態之間重新編碼工具呼叫（`6e7d1513`、`69dcf747`、`5c23390a`）
* 會話留在持有其提示快取的 Key 上，因此固定不會帶來快取未命中；路由狀態（冷卻、固定、輪換、在途）永遠不進入 Agent 程序指紋，所以換 Key 不會重啟程序（`237034e1`、`054348ec`）
* 並行與請求速率按 Key 設限：泳道限制在途請求數，泳道滿時先進有界 FIFO 佇列等待，之後才回 429，滾動一分鐘限制啟動次數（`41956368`、`c166d3b8`）
* 七種策略——順序、輪詢、最少使用、智慧、最低延遲、加權、手動——全部可由本機觀測算出；路由可以設定首 token 期限，同時約束回應標頭和第一個串流 token（`3bec21f2`、`19bdd7e0`）
* 熔斷器按路由組而非 Provider 劃分，未宣告的協定會被探測而不是直接拒絕（`019922e3`、`f98f9be9`）
* 請求帳本記錄一次請求真正走過的路由：因不可用而被跳過的成員與試過但失敗的嘗試分開記錄，追蹤只帶 id 和失敗類型（`60974688`、`b255f3dd`、`6f7d634b`）
* 閘道頁面本身就是一個工作區：可重放每次請求的即時路由圖、可展開的請求歷史、可選取時間範圍的 p50/p95 流量、告警閾值、預設逾時、上游排序，以及會說明保留視窗並先確認的清空操作（`37193353`、`2701cf66`、`660808e9`、`bcfcd751`）
* 會話裡點名的路由就是 Agent 請求的對象，直連 Provider 仍是同一條程式路徑上的單成員路由（`93bad62e`、`d952318e`、`24bbf895`）

**供應商**

* 共享 Provider 記錄是寫入權威：在一處編輯會到達所有綁定它的 Agent，而當 Agent 自己認證時，綁定也可以故意不指定 Provider（`80e59ec7`、`31304b00`、`ff2f31bb`）
* 供應商工作區從零重建：左欄把閘道、供應商和路由組折在同一個「新增」選單下，統一的身份列、底線標籤和分區卡片，設定原地編輯，路由組在自己的頁面上編輯（`9c5f2498`、`e2b94939`、`bc2a7f0c`）
* 預設作為資料發佈，不再自帶模型 id：套用預設時從隨包的 `models.dev` 目錄讀取該廠商條目，包括上下文上限與能力標記，因此預設不會在廠商發新模型的那一刻過時（`f9dfd52c`、`c41fb0e4`、`e8cc0e5f`）
* 手工設定的 Provider 會變成可重複使用範本，放在**使用者自訂**標題下；範本每次讀取時從記錄投影而來，不帶任何密鑰類請求標頭，id 帶 `user:` 前綴因此永不覆蓋內建預設（`c7e58564`、`14cb47e8`）
* 供應商的 Key 列改用遮罩指紋標識憑證，而不是生成的標籤；眼睛按鈕透過一次顯式讀取展示真值，普通快照只帶遮罩（`74162862`）
* 請求標頭覆寫會投射到原生 Agent 和閘道；匯入一次預覽一個來源，大模型清單分頁，儲存前先測試草稿；填好位址與 Key 的草稿會去抓模型；支援按 Key 的模型範圍與代理（`969c147a`、`1a1693e0`、`351c58ae`、`a350748b`、`20536bb6`）
* 路由組只組合 `(Provider, model)` 對：`ProviderGroup` 形態退役，既有列按成員的已啟用目錄遷移為模型組（`c30f9d90`、`bffc1a37`、`429d97b4`）
* 路由組編輯器增加了建議卡片：多家 Provider 都提供的模型會作為一鍵新增的候選出現（`aebf9582`、`19bdd7e0`）

**遠端執行階段（SSH 與 WSL）**

* 桌面端在遠端 Linux 主機上安裝 `vibex-server`，以固定 TLS 憑證在回環上啟動，開啟 `ssh -L` 通道，自己透過 SSH 領取一次性配對碼，再用 Remote Protocol v2 連線（`4aa8b4a6`、`1fe5ad24`、`27403118`）
* 九步開通狀態機負責順序、取消安全點、失敗重試，以及「執行階段 id 只在就緒後才暴露」這一不變量；重複發起會回傳已經在跑的那次嘗試（`d4680f42`、`c94ffa38`、`a1aceab5`）
* 環境探測檢查 Linux、架構、glibc、磁碟餘量、home 可寫、`sha256sum` 和目標埠，並以帶型別的阻斷錯誤回報；Git、`SHELL` 和未知埠只作為警告（`4aa8b4a6`）
* 通道受監管：看門狗每 500 毫秒檢查子程序，並按同一份通道規格重建一次，把重啟或失敗如實呈現（`5bb1e065`）
* 升級是事務性的：新產物裝在目前版本旁邊，執行階段身份保留；起不來的執行階段會回滾到上一版，並啟動、校驗上一版（`ec66c998`、`664923d3`、`613b0981`）
* 解除安裝可以選擇保留 home 目錄，SSH profile 可以編輯、移除和重新開通；已配對的 SSH 連線即使還沒開通也能被刪除（`e0f05f7f`、`399ba89e`、`f4db1824`）
* macOS 遠端主機透過 LaunchAgent 支援，並為其發佈 arm64 與 x86_64 伺服器產物（`349d09bc`、`7472cb31`、`48fa8d6d`）
* WSL2 發行版完全不需要 sshd：上傳、安裝、啟動、等待 localhost 轉發真正可用、在回環上領取配對，並在 `wsl --shutdown` 後恢復（`6de4ca9e`、`812e1684`、`068c669f`、`4ccdd60a`）
* 提供一份可稽核的 root 引導腳本，為沒有 sshd 的主機安裝它，同時不改 `PasswordAuthentication`、不啟用 root、不動防火牆；cloud-init 範本則涵蓋在建立 VM 時就貼上公鑰的廠商（`c5df1c5c`、`bb67ef78`、`7f98abed`）
* 遠端腳本參數會做 shell 轉義，惡意取值會原樣到達腳本；配對碼不會進入伺服器日誌；遠端伺服器日誌可從診斷頁讀取，平台類失敗會附帶恢復指引（`284581cb`、`44322620`、`d51c6b84`、`8c433e57`）
* 遠端執行個體位於工作區分組的**設定 → 遠端執行個體**，始終出現在導覽、搜尋和命令面板中；此前的開發者開關及其環境變數已移除（`ce9d6afa`）
* 標題列的執行階段面板變成已配對執行個體的切換器，底部動作改為開啟設定，而不再攜帶第二套配對表單（`33571d2e`）

**時間線與會話**

* 工具呼叫以可讀結構呈現而不是美化後的 JSON：`路徑: 值` 欄位、待辦清單、以清單呈現的提問與回答、解包後的 harness 輸出信封，編輯或寫入畫成帶 `+N/-M` 的差異（`a354a8c2`、`c408cf72`）
* 只寫了工具名的標題會讓位給呼叫自己的命令、路徑或查詢，`cd <絕對路徑> &&` 前綴不再把命令本身擠過截斷點（`a354a8c2`）
* 活動標頭先講意圖和結果：失敗的呼叫在折疊時就顯示它印出的第一行，結束的命令和 Agent 呼叫顯示耗時，抓取類呼叫有了自己的類型與地球圖示（`c408cf72`）
* 訊息裡引用的工作區圖片——相對、根相對、絕對或 `file://`——會內聯繪製，被限制在工作區內，點擊開啟全視窗預覽；時間線裡的圖片也變成可點縮圖（`42f51cda`、`bcda7984`、`b83584b6`）
* 內建工具面板改為按會話選擇：新建會話頁為每個面板記錄明確的開關，缺省條目跟隨 Agent，分叉或委派會複製這份對應（`2acc9b7a`、`3866693d`、`7b30af79`）
* 長正文透過自己的視埠讀取，執行中的會話開啟時落在歷史而不是目前這輪，上方內容落進來時讀者的位置不會被頂走（`702d42f3`、`6c605ea2`、`5238cd96`）
* 新建會話輸入框增加了全螢幕控制項，自動續跑成為整個 shell 的預設值，無需顯式開啟也會繼續（`a95049b4`、`21080cee`、`fafd85c4`）
* 側欄用與會話列相同的漏斗姿態選單收窄會話清單——全部、執行中、等你處理、未讀、失敗、已置頂——批次操作跟隨可見列（`d52669fe`、`125bea0c`）
* 開啟的編輯器標籤會跟隨磁碟上的改動，淺色主題重新調成冷調中性階梯，模組底色改為實心不透明（`e063cad7`、`f9e4bc2d`）

**市場與管理**

* MCP 市場直接向註冊表提出讀者自己的問題，而不是走一遍有上限的背景目錄，因此深藏在發佈順序裡的名字也能立刻找到；分頁沿著註冊表游標走（`6ff5ddff`）
* 市場條目現在帶上發佈方自己的圖片，遠端條目必需的請求標頭會成為安裝輸入並送入伺服器的 headers 而不是 environment（`c1c02062`、`6ff5ddff`）
* 技能市場改讀一個約一秒回應的公開目錄：首頁排名只解析一次並共享六小時，瀏覽頁把同一個儲存庫折疊到最多四條，安裝則從目錄點名的儲存庫裡取出（`be0ed3e3`、`8b799349`）
* 市場卡片點擊即安裝，MCP 伺服器與技能都支援邊輸入邊搜尋，按功能的 Agent 膠囊用來選擇哪些 Agent 獲得該能力（`3dc52df9`、`c5892f51`、`57649617`、`7d0f9a35`）

**TUI**

* 每個 `鍵 標籤` 圖例都是可點目標：佇列與停靠帶、彈窗頁尾、設定頁尾、新建會話頁的方括號提示都會發佈自己的矩形和它寫明的鍵，點擊走與鍵盤相同的 `handle_key` 路徑（`7d031085`）
* `Chord::from_hint` 按讀者的讀法解析圖例——`^S`、`Space`、`↑`、`J/K`、`Alt+↑↓`——成對的箭頭會拆成兩個單格目標（`7d031085`）
* 佇列帶與停靠帶會捲動以保持游標可見，點擊會經過該帶真正繪製的視窗對應，而不是從矩形頂端數列（`7d031085`）
* 供應商表格可以切換它使用的閘道，並按價格展示套餐預設；匯入的 Key 按其實際作用命名而不是給一句泛泛的警告，放不下的欄會被丟棄而不是硬擠（`47147915`、`69fa7538`、`5e1c0e14`、`5c95e57a`）
* 結束的工具呼叫保持折疊，落在讀者眼前的回答保持展開，`Ctrl+C` 只中斷會話頁（`8a03fd17`、`910913c6`、`080b26aa`）
* 輸入帶的尺寸按輸入框真正繪製的寬度來計算（`0a762e36`）

**行動端**

* 字級階梯按真正繪製的尺寸讀取，連線頁帶上了 Vibex 字標，同步徽標改為文字繪製，CBDT emoji 字型作為 APK 資源隨包發佈（`3220066c`、`1f498fa4`、`08ca01c3`、`b186ed66`）
* 檔案與提交支援邊輸入邊搜尋，時間線捲動時讀者位置保持不變，會話結束時把畫面交還給讀者（`161b650f`、`ca2400c6`、`465a65ab`）
* 連線已死時恢復路徑不再直接中止，新建會話會立即開啟，鍵盤收起時終端保持不動（`2493a86b`、`b43bb055`、`aaef17d9`）

**競技場**

* 在原初六位之外新增十位守衛，共十六場戰鬥：Cursor、Cline、Grok、ZCode、Kimi、CodeBuddy、Antigravity、Devin、Gemini 和 Hermes（`e5168da2`、`5645c96c`、`d6decc70`、`8061402d`、`4973757a`、`450af4d3`、`6b380f76`、`40c419ee`、`8fcdbc62`、`1b9225f4`）
* 每位守衛都有自己的登場、退場和巡遊節奏，每個隨從效果由各自的那場勝利解鎖（`f22f1fa4`、`99af3cd9`、`f724edac`）

## 修復

* 修復閘道頁面的記錄區：整條記錄可點、置中並靠右對齊，記錄在路由圖下仍然可讀，短視窗裡成員卡片仍可捲動（`7125dbec`、`74bdc80a`、`5dbf5adb`、`55c44aa4`）
* 修復路由圖：滾輪不再滾出地圖之外，圖上的未編譯參照被修好，選中請求的重放按它自己的時鐘推進（`7124d834`、`8a138aff`、`95cd5545`）
* 修復閘道對失敗的表述：用閘道自己的錯誤碼回報失敗，服務模型名不再帶路由組 id，顯示可讀名稱而不是內部 id，協定轉換與完整請求指標可見（`a0e96be0`、`dc811559`、`aa5581b4`、`f88cd91f`）
* 修復供應商匯入與草稿：匯入選擇器從空開始並如實回報 Key，請求標頭編輯器開在空物件上，儲存過的草稿不再看起來未儲存，進入表單後 `escape` 仍然有效（`a9742023`、`3eb4cac3`、`a992d77f`、`dddfc731`）
* 修復供應商預設：從 Agent 會說的協定開始，畫廊穩定且不再閃爍，提示裡點出實際套用的預設，本機 Provider 沒有 Key 也能拉模型（`2acd1033`、`d01cfb4f`、`b6170ba0`、`a5bdabeb`）
* 修復共享 Provider：刪除墓碑可以修復，範本副本不再自己變成範本，已被該 Agent 使用的 Provider 不再出現在候選裡（`ce94f22d`、`14cb47e8`、`cc39b24e`）
* 修復 SSH 連線：未配對的連線可以被移除，空狀態可以直接開啟 SSH 設定，新增流程以對話框開啟，連線狀態使用框架的狀態角色（`f4db1824`、`214c2a79`、`8e8e617e`、`08770715`）
* 修復 bootstrap：詢問使用者指定的 Linux 帳戶而不是假設 `ubuntu`，在沒有 PAM 時拒絕鎖定帳戶，在 systemd 類主機上建立 sshd 執行目錄，在暫存目錄校驗 payload 雜湊（`7f98abed`、`0b2aa0ec`、`e73a9032`、`600bd900`）
* 修復 WSL：為保留埠而不是已釋放埠拒絕轉發，`wsl --shutdown` 後重試恢復（`81d0a35e`、`b29aeec6`）
* 修復時間線：列在底部邊緣切換時不再推動時間線，折疊控制項的按下不再進入視窗級選取，活動列寬在折疊控制項旁邊保持（`c9a53a35`、`ed4a756f`、`ddbbca24`）
* 修復自動繼續：回合被停止時暫停下一次繼續（`36ffab18`）
* 修復執行階段切換：等待超過期限的切換仍然生效，初始準備期間的選中變化會被接受（`9fc56b16`、`0b825293`）
* 修復側欄：背景重新整理不再和讀者搶捲動位置，已封存頁刪除全部時每一列都被刪掉（`189eab4a`、`5c9a3793`）
* 修復 TUI：匯入的 Key 按其作用命名，放不下的供應商欄被丟棄（`5e1c0e14`、`5c95e57a`）
