MCP 伺服器和 Skill 擴充套件 Agent 能做什麼、知道什麼。兩者都在配置中心裡管理，都是**逐 Agent 啟用**的。

## MCP 伺服器

MCP（Model Context Protocol）伺服器為 Agent 提供額外工具。Vibex 支援三種傳輸方式：

| 傳輸 | 適用場景 |
| --- | --- |
| **stdio** | 本地程序。填寫啟動命令、引數和環境變數。 |
| **HTTP** | 遠端服務。填寫 URL 和請求頭。 |
| **SSE** | 遠端服務，Server-Sent Events。填寫 URL 和請求頭。 |

### 從市場安裝

開啟 **配置中心 → MCP**，預設進入 **MCP 市場**：

1. 搜尋或分頁瀏覽。卡片顯示傳輸方式、來源、命令摘要和已啟用的 Agent。
2. 點 **安裝**，先確認將要儲存的命令、傳輸方式、環境變數和請求頭。
3. 選擇哪些 Agent 接收這個 MCP 伺服器。
4. 安裝完成後，條目會出現在左側的已安裝列表裡；可以 **重新安裝** 或編輯。

<Note>
  市場搜尋會邊輸入邊查上游目錄。安裝前請確認伺服器來源和命令；市場條目不是 Vibex 背書的執行檔。
</Note>

### 手動新增

1. 在 MCP 列表點選 **新建 MCP 服務**。
2. 填寫 **名稱**，選擇傳輸方式。
3. 按傳輸方式填寫 **命令** / **引數** / **環境變數**，或 **URL** / **請求頭**。
4. 選擇作用域：**使用者** 或 **工作區**。
5. 儲存，然後在資源卡片上點選 **驗證**。
6. 在卡片下方的 **Agent 啟用範圍** 區域，為需要使用它的 Agent 開啟開關。

也可以使用 **匯入已有 MCP** 從其它 Agent 的原生配置裡讀取候選。匯入會先顯示預覽，不會靜默覆蓋。

<Info>
  校驗是**離線**的：它只檢查必填欄位和 URL 格式（HTTP/SSE 必須以 `http://` 或 `https://` 開頭），不會啟動程序，也不會發起網路請求。所以校驗通過不代表伺服器真的能連上。
</Info>

<Warning>
  MCP 工具可能讀取檔案、訪問網路或修改外部系統。先確認伺服器來源和權限，再把它關聯到 Agent。
</Warning>

## 技能

Skill 是一份 `SKILL.md` 加上它引用的輔助資源，用來給 Agent 補充可複用的領域知識或操作流程。來源可以是：

| 來源 | 說明 |
| --- | --- |
| `manual` | 直接在 Vibex 裡手寫。 |
| `local_folder` | 本地資料夾。 |
| `git_repo` | Git 倉庫。 |
| `marketplace` | 市場來源。 |

### 從市場安裝

開啟 **配置中心 → Skill**，預設進入 **Skill 市場**：

1. 搜尋或分頁瀏覽。卡片顯示來源、安裝量、官方標記和已啟用的 Agent。
2. 點 **安裝**，在提交前閱讀完整的 `SKILL.md` 正文、檔案清單和被拒絕的檔案。
3. 選擇哪些 Agent 接收這個 Skill。
4. 安裝完成後可以 **重新安裝**；被撤下的條目會優先說明。

### 手動新增

1. 開啟 **配置中心 → Skill**，點選 **新建 Skill** 或 **匯入已有 Skill**。
2. 填寫 **名稱**、**描述** 和 **技能說明**（也就是 `SKILL.md` 的正文）。
3. 儲存並 **驗證**。
4. 在 **Agent 啟用範圍** 裡為需要的 Agent 開啟開關。

配置好後，在輸入框中輸入 `$` 就能查詢並插入已啟用的 Skill。

<Warning>
  Skill 的正文和附帶檔案會進入 Agent 的上下文。安裝前閱讀內容，尤其是來自市場的 Skill；不要安裝會要求憑據或執行未知命令的條目。
</Warning>

## Prompt

Prompt 是配置中心裡的另一種可複用資源，適合反覆輸入同一段指令：

- 在 **配置中心 → Prompt** 新建，填寫名稱和正文。
- 在輸入框裡輸入 `/` 搜尋並插入。
- Prompt 也可以按 Agent 啟用。
- Prompt 是純文本，不攜帶檔案或工具；需要這些時用 Skill。

## 匯出到 Agent 原生配置

MCP、Skill 和 Prompt 都可以寫入 Agent 自己的配置檔案，這樣 Agent 的其它入口（例如外部 CLI）也能用上同一份配置。

在資源卡片上使用 **預覽匯出** → **應用** → **回滾**：

1. **預覽匯出** 會列出將要改動或新建的檔案。
2. 確認無誤後再 **應用**。
3. 出問題時從同一處 **回滾** 恢復。

寫入目標取決於 Agent，例如 Codex 的 `~/.codex/config.toml`、Claude 的 `~/.claude/settings.json`，以及各 Agent 的技能目錄。

<Warning>
  **應用之前一定要看預覽。** Vibex 預設不改寫 Agent 的原生 home 配置，只有你明確應用時才寫入。
</Warning>

## 作用域與安全

使用最小作用域，避免把專案專屬工具暴露給所有專案。MCP 伺服器當前只提供 **使用者** 和 **工作區** 兩種作用域。

- 先停用，再刪除；停用會保留記錄，便於恢復。
- 刪除資源不會刪除已經寫入 Agent 原生目錄的檔案；用匯出預覽裡的回滾處理。
- 任何日誌和診斷資料都必須去掉 token、私鑰、環境變數值、提示詞和檔案內容。
- 市場安裝會寫入執行階段 home；不要把不受信任的市場條目直接啟用給所有 Agent。
