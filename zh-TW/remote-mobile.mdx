行動端是 Vibex 的原生遠端夥伴。權威執行環境（桌面端內嵌的本機執行環境，或自託管的 `vibex-server`）負責 Agent、檔案、Git、終端機、供應商和權限；行動端透過 Remote v2 要求投影並傳送具型別的操作，**不在本機執行 Agent**。

## 先確認要連線哪個權威執行環境

| 你的情況 | 應該連線 |
| --- | --- |
| 手機和電腦在同一個網路，只想在手機上繼續電腦上的會話 | 桌面端內嵌的本機執行環境 |
| 想讓會話常駐在一台伺服器上，電腦和手機都接進去 | 自託管的 `vibex-server`，請見[自託管無頭執行環境](/zh-TW/self-hosted-server) |

如果你要連線的是 `vibex-server`，**請先依照該頁的說明將它啟動並取得配對碼或連線字串**，再回到這裡配對用戶端。

## 連線方式

| 方式 | UI 名稱 | 適用情境 |
| --- | --- | --- |
| Direct | **Direct HTTPS** | 用戶端可以透過可達位址直連權威端。 |
| Tailnet | **Tailscale Serve** | 你使用 Tailscale 等私有網路，權威端不暴露公用連接埠。 |
| Relay | **Self-hosted Relay** | 無法直連時，透過自託管 Relay 轉送加密訊框。 |
| 區域網路 | **Local network pairing** | 零設定區域網路探索，主機名稱格式為 `vibex-lan.local`。 |

Relay 不會儲存、不會解密業務資料，只處理房間、連線和加密訊框等路由中繼資料。詳見[自託管 Relay](/zh-TW/relay)。

## 配對

### 路徑一：桌面端產生，手機掃碼

適用於「手機連我的電腦」。

1. 在桌面端標題列點選 **Pair mobile**，開啟 **Connect a mobile device** 對話方塊。
2. 選擇連線方式並啟用，等待狀態變成 **Online**。
3. 點選 **Generate pairing QR code**，取得短效期的 QR Code 和連結。
4. 在手機上開啟 Vibex，選擇 **Use QR Code** 掃碼，或貼上連結。
5. 兩端核對 **Verification code** 是否一致，並在桌面端點選 **Code matches, allow**。
6. 完成握手後，手機會收到初始投影和會話清單。

這個連結的格式是 `vibex://open/<transport>#/pair/<offer>`，有效期為 **60–120 秒**，只能使用一次。

### 路徑二：伺服器列印，用戶端填入

適用於「桌面端和手機都連我的伺服器」。

`vibex-server` 啟動時會列印一次性配對碼和連線字串：

```text
pairing_code=123-456-789
pairing_link=vibex://pair#/code/<payload>
tls_fingerprint=sha256:...
```

連線字串中同時帶有**伺服器位址、一次性配對碼和伺服器憑證**。用戶端填入它的好處是：使用自簽憑證的伺服器不需要系統 CA，因為用戶端在發出第一個要求前就固定了這張憑證。

- **桌面端**：開啟標題列的 **Runtime** 管理員，新增執行環境，選擇 **Connection string** 分頁貼上，或選擇 **Pairing code** 分頁填入位址和配對碼。
- **行動端**：選擇 **Pair with a Cloud Server**，填入位址和配對碼；或把連線字串貼到 **Pair with Connection String**。

配對碼預設有效 **5 分鐘**，最長 30 分鐘，只能使用一次，伺服器端只儲存它的 SHA-256 雜湊。需要新的配對碼時，在伺服器上執行 `vibex-server pairing-code`。

<Warning>
  QR Code 和連線字串等同於一次性的登入憑據。不要將它發佈到聊天、Issue 或任何公開管道。
</Warning>

## 權限等級

配對時選擇裝置的權限等級，等級由**發起端**在建立配對時決定，用戶端無法自行提高權限：

| 等級 | UI 名稱 | 允許的操作 |
| --- | --- | --- |
| `read_only` | **Read only** | 讀取專案、會話、檔案和供應商設定摘要。所有寫入操作都會被拒絕並記入稽核。 |
| `approve_only` | **Approve only** | 上述讀取權限，加上核准或拒絕權限要求和詢問表單。 |
| `full_control` | **Full control** | 全部操作：傳送訊息、讀寫檔案、Git 寫入操作、終端機輸入、供應商設定修改和裝置管理。 |

授予最小夠用的權限。權威端可以隨時撤銷裝置，撤銷會立即中斷該裝置的活動連線。

## 行動端能做什麼

| 能力 | 說明 |
| --- | --- |
| 會話 | 檢視時間線、傳送後續訊息、重新命名、刪除、分支、批次選取。 |
| 核准與詢問 | 核准或拒絕權限要求，填寫 elicitation 表單。 |
| 檔案 | 瀏覽檔案樹、依名稱或內容搜尋、**編輯並儲存檔案**。 |
| Git | 檢視狀態與差異、stage / unstage / revert / commit、檢視歷程、fetch / push、建立 worktree。 |
| 終端機 | 建立、附加、調整大小、傳送輸入。 |
| 用量 | 只顯示會話數量，並提示 "Usage details are available on the desktop host."。 |

**行動端沒有 Config Center**，不能管理 Agent、供應商、MCP 或 Skills。它的 Settings 只包含 Connection、Session timeline、Appearance、Notifications 和 About。

所有寫入操作的實際結果一律由權威執行環境產生；行動端顯示的是它的投影。

## 斷線與重新連線

網路切換或應用程式恢復後，行動端會重新驗證並要求 catch-up：先顯示權威的會話和時間線狀態，再恢復即時事件。

| 現象 | 處理 |
| --- | --- |
| `stale` | 等待權威重新整理，不要根據舊快照重複執行命令。 |
| `revoked` | 裝置已被撤銷，必須重新配對。 |
| `resync_required` | 用戶端偵測到序號或游標缺口，正在重新同步；以權威端的狀態為準。 |

## 安全性檢查

- 權威端預設只監聽 loopback。要跨網路使用，請透過 Tailnet、自簽憑證（區域網路）或受控的 HTTPS/WSS 反向代理來發佈。
- 不要使用未驗證的公用網路監聽。
- 不要把 room id 或配對碼當作長期憑據。
- 定期在裝置清單中檢查已配對裝置，並及時 **Revoke** 不再使用的裝置。
