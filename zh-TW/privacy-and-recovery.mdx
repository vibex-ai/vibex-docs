---
title: "隱私與恢復"
description: "了解 Vibex 的本機儲存、遠端隱私與重新啟動行為。"
---

Vibex 採本機優先模型：桌面端保存專案、工作區、會話、時間線、供應商設定、終端機中繼資料與遠端裝置記錄。遠端連線只傳送經授權的投影。

## 資料位置

- SQLite 保存權威中繼資料和可恢復的會話狀態。
- 工作區檔案仍在你選擇的本機目錄或 Git worktree。
- Agent、終端機與 Git 程序由桌面端執行。
- 自託管 Relay 只轉發加密框，不保存業務資料庫。

Relay 房間與連線是短暫狀態；日誌應只包含路由、計數與時序中繼資料。

## 重新啟動與陳舊狀態

重啟後桌面端依持久化記錄載入工作區、會話和設定。資料庫中的 `running` 只是上次觀察到的狀態，不代表程序仍在執行。遺失的終端機會標記為 stale；恢復前先檢查實際程序和工作區。

<Info>
  看到 stale 或 resync required 時，先執行權威重新整理，再決定是否重試。不要因行動端暫時沒有即時事件就重複執行有副作用的命令。
</Info>

## 裝置撤銷

從桌面端遠端裝置清單撤銷裝置後，活動連線會收到 revoked 並關閉。再次使用必須重新配對；舊 QR、grant 或 ticket 不應繼續使用。

## 診斷與備份

診斷和備份必須脫敏：移除 token、私鑰、配對碼、提示詞、檔案內容、Git diff 和終端機位元組；保留版本、平台、結構化錯誤碼、時間和不敏感資源 id。備份 SQLite 前關閉桌面端或使用專案提供的安全流程。恢復後檢查工作區路徑、裝置授權和 secret reference。

## 外部服務邊界

Agent 和 MCP 可能把你明確提供的上下文傳送到供應商或外部服務。使用前閱讀對方隱私政策，並用工作區範圍、權限核准與最小附件控制資料範圍。
