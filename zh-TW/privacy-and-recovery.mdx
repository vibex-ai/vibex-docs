title: "隱私與復原"
description: "了解 Vibex 的本機儲存、重新啟動復原行為和診斷資料界線。"
---

Vibex 採用本機優先模型：權威執行環境會儲存專案、工作區、會話、時間線、供應商設定、終端機中繼資料和遠端裝置記錄。遠端連線只會把獲得授權的投影傳送給用戶端。

## 資料在哪裡

| 資料 | 位置 |
| --- | --- |
| 權威中繼資料與會話狀態 | 權威執行環境 home 中的 SQLite 資料庫 |
| 專案檔案 | 你選擇的本機目錄，或 Vibex 託管的 Git worktree |
| 供應商憑據 | 作業系統的鑰匙圈；無頭主機上退回只有擁有者可讀取的金鑰檔案 |
| Agent 安裝 | 權威執行環境的 home 目錄 |
| Relay 資料 | **無**。Relay 只轉送加密訊框，不儲存業務資料庫 |

Relay 的房間和連線是暫時狀態。Relay 日誌應只包含路由、計數和時序中繼資料。

## 重新啟動後會保留什麼

重新啟動權威執行環境後，它會根據持久化記錄重新載入工作區、會話和設定。關鍵差異在於：

**會保留（寫入 SQLite）：**
- 專案、工作區和工作區模式
- 會話、時間線事件和訊息
- 供應商設定、MCP 伺服器、Skills
- 終端機**中繼資料**（分頁名稱、繫結關係）
- 遠端裝置授權

**不會保留（僅記憶體）：**
- 正在執行的 Agent 處理程序
- 終端機**會話內容與滾動緩衝區**
- 活動連線和即時事件訂閱

<Info>
  資料庫中的 `running` 只是**上次觀察到的狀態**，不代表處理程序仍在執行。重新啟動後看到 `running` 的會話時，請先確認實際處理程序是否存在，再決定是否重試。
</Info>

遺失的終端機會被標記為 `stale`。請以新的終端機快照為準，不要根據舊快照重複執行命令。

## 裝置撤銷

在權威執行環境的裝置清單中撤銷裝置後，該裝置的活動連線會立即收到 `device_revoked` 並關閉。

- 要重新使用需要**重新配對**。
- 舊的 QR Code、連線字串、授權和 ticket 全部失效，不應繼續使用。
- 撤銷操作會寫入裝置稽核記錄。

## 診斷資料

**Settings → Data & Diagnostics** 提供診斷匯出入口。匯出前請確認脫敏結果：

**必須移除：**
- token、私鑰、配對碼和連線字串
- 提示詞全文與檔案內容
- Git diff 和終端機原始位元組

**可以保留：**
- 版本、發行通道和平台
- 結構化錯誤碼
- 脫敏後的時間戳記
- 不敏感的資源 id

<Warning>
  診斷匯出是**單向**的：一旦提交到公開管道就無法收回。匯出後請先自己讀一遍，再決定是否上傳。
</Warning>

## 備份

- 備份 SQLite 之前先**關閉**權威執行環境，或使用專案提供的安全備份流程。
- 還原後檢查工作區路徑、裝置授權和供應商憑據引用是否仍然有效。
- 無頭執行環境的資料預設位於 `/data`；將它掛載為持久性磁碟區，容器重建後會話才會保留。

## 清理資料

**Settings → Data & Diagnostics** 中可以分類清理本機儲存：會話與附件、終端機資料、診斷資料。這些操作**無法復原**。

<Warning>
  重設設定只會影響偏好；刪除資料庫、資料目錄或工作區目錄是不同的破壞性操作。執行前請先確認你確實不再需要這些資料。
</Warning>

## 外部服務界線

Agent 和 MCP 伺服器可能會把你明確提供的內容傳送到供應方或外部服務。使用前請閱讀對應服務的隱私權政策，並透過最小作用範圍、權限核准和最小附件來控制資料範圍。

配對到遠端權威執行環境意味著：**該權威執行環境的管理員可以看到你的會話資料**。自託管時這個管理員就是你；連線到他人的執行環境前請先確認這一點。
