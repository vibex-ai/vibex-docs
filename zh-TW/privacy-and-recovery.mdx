Vibex 採用本地優先模型：權威執行階段儲存專案、工作區、會話、時間線、供應商設定、終端機後設資料、瀏覽器配置、電腦操作審計、路由臺帳和遠端裝置記錄。遠端連線只把獲得授權的投影傳送給客戶端。

## 資料在哪裡

| 資料 | 位置 |
| --- | --- |
| 權威後設資料與會話狀態 | 權威執行階段 home 中的 SQLite 資料庫 |
| 專案檔案 | 你選擇的本地目錄，或 Vibex 託管的 Git worktree |
| 供應商憑據 | 作業系統的鑰匙串；無頭主機上退回僅屬主可讀的金鑰檔案 |
| Agent 安裝 | 權威執行階段的 home 目錄 |
| 瀏覽器配置 | 執行階段 home 下隔離的瀏覽器 `user-data-dir`；匯入的登入狀態也在其中 |
| 電腦操作記錄 | 執行階段 home 下的脫敏審計記錄；不儲存螢幕畫素或輸入文本 |
| 閘道器請求臺帳 | 執行階段資料庫；只含 token、延遲、狀態和路由後設資料 |
| TUI 偏好 | `~/.vibex/tui-interface.json`、`~/.vibex/tui-keys.toml`（或對應 home） |
| SSH / WSL 連線 | 桌面端 home 下的 `ssh-connections.json`、`wsl-connections.json` 和遠端執行階段登錄檔 |
| Relay 資料 | **無**。Relay 只轉發加密幀，不儲存業務資料庫 |

Relay 的房間和連線是短暫狀態。Relay 日誌應只包含路由、計數和時序後設資料。

## 重啟後什麼會保留

重啟權威執行階段後，它會根據持久化記錄重新載入工作區、會話和配置。關鍵區別在於：

**會保留（寫入 SQLite 或執行階段 home）：**
- 專案、工作區和工作區模式
- 會話、時間線事件、訊息、目標、委派關係和歸檔狀態
- 供應商設定、共享 Provider、路由組、MCP 伺服器、Skill、Prompt
- 終端機**後設資料**（標籤名、繫結關係）
- 未傳送的輸入框草稿和定時傳送
- 瀏覽器隔離配置、匯入的登入狀態
- 遠端裝置授權、SSH/WSL 連線配置
- 工作台背景、主題和 TUI 偏好

**不會保留（僅記憶體）：**
- 正在執行的 Agent 程序
- 終端機**會話內容與滾動緩衝區**
- 瀏覽器開啟的標籤和即時畫面
- 活動連線和即時事件訂閱
- 正在進行的電腦操作會話

<Info>
  資料庫裡的 `running` 只是**上次觀察到的狀態**，不代表程序仍在執行。重啟後看到 `running` 的會話時，先確認實際程序是否存在，再決定是否重試。
</Info>

丟失的終端機會被標記為 `stale`。以新的終端機快照為準，不要根據舊快照重複執行命令。

## 裝置撤銷

在權威執行階段的裝置列表中撤銷裝置後，該裝置的活動連線會立即收到 `device_revoked` 並關閉。

- 重新使用需要**重新配對**。
- 舊的二維碼、連線串、授權和 ticket 全部失效，不應繼續使用。
- 撤銷操作會寫入裝置審計記錄。
- SSH/WSL 執行階段只能通過桌面端的隧道訪問，手機不能直接配對。

## 診斷資料

**設定 → 資料與診斷** 可以清理診斷資料。目前版本沒有面向使用者的診斷匯出頁面；如果你透過開發者工具匯出診斷包，匯出前請確認脫敏結果：

**必須移除：**
- token、私鑰、配對碼和連線串
- 提示詞全文與檔案內容
- Git diff 和終端機原始位元組
- 瀏覽器 Cookie、localStorage 和登入狀態
- 電腦操作的輸入文本、剪貼簿內容和截圖

**可以保留：**
- 版本、釋出通道和平台
- 結構化錯誤碼
- 脫敏後的時間戳
- 不敏感的資源 id

<Warning>
  診斷匯出是**單向**的：一旦提交到公開渠道就無法收回。匯出後請先自己讀一遍再決定是否上傳。
</Warning>

## 備份

Vibex 目前沒有一鍵備份按鈕。可靠的做法是備份整個**執行階段 home**：

1. 關閉使用該 home 的執行階段（桌面端、TUI 或無頭服務）。
2. 複製整個 home 目錄，包括 `vibex.db`、`vibex.db-wal`、`vibex.db-shm`、身份金鑰、Agent 安裝、瀏覽器配置和憑據引用。
3. 恢復時把備份放回一個空目錄，再讓執行階段指向它。
4. 恢復後檢查工作區路徑、裝置授權和供應商憑據引用是否仍然有效。

<Warning>
  只複製 `vibex.db` 而不復制 WAL/SHM 可能得到不一致的資料庫。執行階段正在寫入時不要直接複製資料庫檔案。
</Warning>

無頭執行階段的資料預設位於 `/data`；把它掛載為持久卷，容器重建後會話才會保留。SSH/WSL 執行階段的資料在遠端 home 的 `~/.local/share/vibex/server` 下。

## 從候選版本匯入資料

穩定版與候選版是兩個獨立應用，擁有各自的應用身份和資料目錄（`desktop-stable` 與 `desktop-rc`），因此穩定版安裝後從空資料開始。

要繼承候選版本的工作，開啟 **設定 → 資料與診斷 → 本機儲存 → 從 RC 版本匯入資料** 並確認：

1. Vibex 先對候選版資料庫做快照。
2. 把快照遷移到目前版本的 schema，並校驗副本。
3. 在下次啟動時換入；工作區、會話與供應商設定一併帶過來。
4. 匯入失敗時保留目前資料，不匯入任何內容。

首次啟動時如果偵測到旁邊的候選版資料，也會彈出一次提示，提供 **匯入資料** 與 **暫不匯入**。候選版安裝本身永遠不會被修改，因此可以繼續把它作為退路。

<Warning>
  **匯入是單一方向：候選版到穩定版。** 不要反過來把穩定版資料庫拷進候選版目錄，兩者的 schema 可能不一致。
</Warning>

## 清理資料

**設定 → 資料與診斷** 中可以分類清理本地儲存：會話與附件、終端機資料、診斷資料。這些操作**不可回滾**。

瀏覽器資料可以在 **設定 → 瀏覽器 → 清除瀏覽器資料** 裡單獨清理；電腦操作記錄和網關臺帳會隨執行階段資料一起保留，除非你清理對應資料庫。

<Warning>
  重置設定只影響偏好；刪除資料庫、資料目錄或工作區目錄是不同的破壞性操作。執行前先確認你確實不再需要這些資料。
</Warning>

## 外部服務邊界

Agent、MCP 伺服器、共享 Provider 和瀏覽器頁面可能把你明確提供的上下文傳送到供應方或外部服務。使用前請閱讀對應服務的隱私政策，並通過最小作用域、權限核准和最小附件控制資料範圍。

配對到遠端權威執行階段意味著：**該權威執行階段的管理員可以看到你的會話資料**。自託管時這個管理員就是你；連線到他人的執行階段前請確認這一點。
