**配置中心**是 Vibex 的配置入口，從側欄的 **配置中心** 按鈕或系統托盤開啟。它把 Agent 執行階段、模型供應商、MCP 伺服器、Skill 和可複用 Prompt 集中在一處，併為每項資源顯示狀態和驗證結果。

## 分區

配置中心當前提供五個主分區：

| 分區 | 用途 |
| --- | --- |
| **Agent** | 新增、安裝、升級、登入和管理 Agent 執行階段；在所選 Agent 的詳情裡配置它自己的**模型供應商設定**。 |
| **供應商** | 管理共享 Provider、Key、模型、路由組和本地模型閘道器。 |
| **MCP** | 從市場安裝或手動新增 MCP 伺服器，並逐個 Agent 啟用。 |
| **Skill** | 從市場安裝或匯入 `SKILL.md` 能力包，並逐個 Agent 啟用。 |
| **Prompt** | 編寫可複用 Prompt，在輸入框裡用 `/` 插入。 |

<Note>
  **模型供應商設定**不是獨立分區。每個 Agent 可以有自己的模型供應商設定；**共享供應商**和**路由組**在 **供應商** 分區裡。兩者的關係見[供應商、路由組與本地閘道器](/zh-TW/providers-and-gateway)。
</Note>

## 通用操作

### 搜尋與篩選

每個分區的左側列表頂部都有搜尋框。Agent 可以按名稱、id 和描述搜尋；供應商可以按名稱、地址、模型和 Key 搜尋；MCP、Skill 和 Prompt 可以按名稱或描述搜尋。列表會記住你的排序和篩選，直到你改變它。

### 儲存與驗證

1. 填寫欄位並儲存。
2. 在資源卡片上點選 **驗證** 執行校驗。MCP 和 Skill 的校驗是**離線**的：檢查必填欄位、格式和作用域，不會啟動程序或發起網路請求。
3. 對模型供應商可以額外執行 **測試連線**，它會真實呼叫一次模型介面。

<Warning>
  **測試連線**、**拉取模型** 和真實會話都會訪問供應方網路並可能產生費用。確認地址、模型和權限後再執行。
</Warning>

### 作用域

部分資源可以設定作用範圍：

- **使用者**：對你所有專案可見。
- **工作區**：只對當前工作區可見。
- **專案**：跟隨專案約定（部分資源支援）。
- **全域性**：作為全域性預設，謹慎使用。

開始配置時先選最小作用域。MCP 伺服器當前只提供 **使用者** 和 **工作區** 兩種。

### 逐 Agent 啟用

資源（MCP、Skill、Prompt、Provider）和 Agent 之間是**逐 Agent 啟用**的關係。資源卡片下方的 **Agent 啟用範圍** 區域為每個已新增的 Agent 提供一個開關；只有開啟開關的 Agent 才會載入該資源。

不需要某個資源時先**停用**，而不是立刻刪除——停用會保留記錄，便於之後恢復。刪除資源會移除配置，但不會刪除已經寫入 Agent 原生目錄的檔案；需要時用匯出預覽裡的回滾。

### 憑據

Vibex 使用 secret reference 或作業系統的安全儲存儲存憑據。桌面端優先使用系統鑰匙串；沒有可用鑰匙串的主機退回僅屬主可讀的檔案。

- 已儲存的 Key 預設掩碼顯示，點眼睛圖示可以臨時檢視。
- 沒有改動過的欄位不會重寫已儲存的值；留空儲存會保留原值。
- 要清除憑據，使用明確的 **清除** 操作，而不是把輸入框留空。
- 不要把 token、私鑰、完整環境變數、提示詞或檔案內容貼上到配置描述或診斷日誌中。

## Agent 分區

左側按狀態分組：已啟用、已新增但停用、尚未新增。每個 Agent 的詳情包含：

- **Agent 安裝**：安裝、檢查更新、升級、回滾到固定版本、解除安裝託管執行階段。
- **原生憑證**：登入 Agent 自己的賬號，重新整理認證方式、驗證賬號、重新整理模型、重新認證、退出登入。
- **模型供應商設定**：這個 Agent 自己的地址、憑據、模型和思考檔位。
- **內建工具**：按 Agent 開關終端機、瀏覽器、電腦操作等工具面板。

詳見[Agent 與供應商設定](/zh-TW/agents-and-providers)。

## 供應商分區

**供應商**頁把每個共享 Provider 只列一次，並顯示哪些 Agent 正在使用它。頂部固定一行是**閘道器**，側欄有 **供應商** 和 **路由組** 兩個標籤。

- **供應商**：地址、憑據、Key、模型、請求頭、代理、請求體欄位。
- **路由組**：把多個 Provider 或模型組合成一個 Agent 可請求的名字，設定策略、故障轉移、限制和可見性。
- **閘道器**：本機迴環端點，負責路由、協議轉換、冷卻、重試和請求臺賬。

詳見[供應商、路由組與本地閘道器](/zh-TW/providers-and-gateway)。

## MCP 與 Skill

兩個分區預設開啟**市場**，可以直接搜尋、分頁瀏覽和安裝：

- **MCP 市場** 顯示傳輸方式、命令、環境變數和請求頭；安裝前可以確認將要儲存的命令。
- **Skill 市場** 顯示 `SKILL.md` 正文、檔案清單、安裝量和來源；安裝前可以閱讀完整內容，並選擇哪些 Agent 接收。
- 已安裝的條目提供 **重新安裝**；被撤下的條目會優先說明。
- 也可以 **新建** 或 **匯入已有** MCP / Skill。

詳見[MCP 與技能](/zh-TW/mcp-and-skills)。

## Prompt

**Prompt** 分區儲存可複用的提示詞正文。儲存後，在輸入框裡輸入 `/` 就能搜尋並插入；Prompt 也可以按 Agent 啟用。

Prompt 與 Skill 的區別：Prompt 是一段可插入的文本，Skill 是一個帶檔案和說明的能力包。需要給 Agent 增加工具或領域知識時用 Skill；需要反覆輸入同一段指令時用 Prompt。

## 匯出到 Agent 原生配置

MCP、Skill 和 Prompt 可以寫入 Agent 自己的配置檔案，讓外部 CLI 也能用上同一份配置。

在資源卡片上使用 **預覽匯出** → **應用** → **回滾**：

1. **預覽匯出** 會列出將要改動或新建的檔案。
2. 確認無誤後再 **應用**。
3. 出問題時從同一處 **回滾** 恢復。

寫入目標取決於 Agent，例如 Codex 的 `~/.codex/config.toml`、Claude 的 `~/.claude/settings.json`，以及各 Agent 的技能目錄。

<Warning>
  **應用之前一定要看預覽。** Vibex 預設不改寫 Agent 的原生 home 配置，只有你明確應用時才寫入。應用後可以從同一處回滾。
</Warning>

## 配置出現問題時

1. 確認資源的作用域和啟用狀態。
2. 執行 **驗證** 看是否有結構化錯誤。
3. 確認該資源已在目標 Agent 的 **Agent 啟用範圍** 裡開啟。
4. 檢查當前連線的是哪個權威執行階段——本機和遠端執行階段的配置是分開的。
5. 如果重啟後狀態不一致，見[故障排查](/zh-TW/troubleshooting)。不要直接刪除 SQLite 資料庫。
