---
title: "Agent 會話"
description: "建立、觀察、暫停、分支與恢復 Vibex Agent 會話。"
---

會話把一次開發任務的輸入、Agent 輸出與工具操作保存為結構化時間線。桌面端保存權威時間線，行動端只顯示遠端投影。

## 建立會話

1. 選擇目標工作區。
2. 在 Composer 頂端選擇 Agent、供應商設定、模型、推理深度與 conversation mode。
3. 輸入任務。用 `/` 選 Prompt、`@` 引用檔案、`$` 插入 Skill，也可以加入附件。
4. 傳送前確認工作區和權限範圍。Agent 可能需要讀取檔案、執行終端機命令或請求授權。

切換 Agent 或模型只影響後續執行。時間線中的訊息會保留產生它的執行身份。

## 閱讀時間線

| 項目 | 你會看到什麼 |
| --- | --- |
| 使用者與 Agent 訊息 | Markdown 文字與附件。 |
| reasoning | Agent 的推理摘要，是否顯示取決於 Agent 與設定。 |
| plan | 待辦步驟與進度。 |
| tool/process details | 工具名稱、參數摘要、程序與退出結果。 |
| permission approval | 等待你核准或拒絕的操作。 |
| elicitation | Agent 要求你填寫的結構化表單。 |
| delegation | 子 Agent 或委派任務的狀態和結果。 |
| 狀態事件 | 執行、排隊、等待、完成、失敗、停止與重連。 |

工具參數、終端機輸出和檔案差異可能含有敏感內容。分享診斷前先脫敏。

## 控制執行

- **Stop**：停止目前執行；已寫入的檔案或已執行的命令不會自動回復。
- **Continue**：在同一會話繼續傳送任務。
- **Retry**：依 Agent 支援的重試語義重新執行失敗回合；不確定外部操作是否已執行時，先核對結果。
- **Fork**：從目前時間線建立分支會話。
- **Rename**：修改會話標題，不改變 Agent 上下文。
- **Edit message**：編輯尚未作為新執行依據的訊息；已完成的時間線事件不會被改寫。
- **Resume**：從持久化歷史恢復會話。

<Warning>
  停止 Agent 只停止執行，不會撤銷檔案、Git 或外部服務變更。請分別檢查 Git diff 與終端機。
</Warning>

## 佇列、自動繼續和委派

執行期間傳送的後續訊息可以進入佇列。桌面端會顯示排隊順序，並在目前回合結束後按順序提交；取消或刪除佇列項目不會回復已完成的操作。

啟用自動繼續時，只有符合會話設定和 Agent 能力的回合會自動推進。權限請求、elicitation、失敗或需要使用者選擇時會暫停等待。**Delegation** 會為子 Agent 建立獨立狀態，並把進度和最終結果關聯回父會話。

## 權限與詢問表單

Agent 請求終端機、檔案寫入或其他受保護能力時，時間線會顯示原因與範圍。選擇 **Approve** 或 **Deny**，結果會記錄在時間線。取消 elicitation 表單會傳回取消結果，不會隱式核准。

## 匯入本機歷史

使用 **Local history import** 掃描本機歷史，再選擇要匯入的會話和目標工作區。目前支援 Claude Code、Codex、OpenCode、Gemini CLI、Cline、Hermes、CodeBuddy Code、Kimi Code、Pi、Grok、Cursor、DeepSeek Harness、ZCode 和 Google Antigravity。

掃描器只保存標題、時間、工作區提示、訊息數量和來源路徑等受限中繼資料。確認選擇後才重新讀取並一次性寫入時間線；已匯入、已刪除或找不到的來源會分別標記，不會重複匯入。憑證、私鑰和完整 Agent home 設定不會匯入。

## 搜尋和通知

使用 `cmd-f`（Windows/Linux 通常為 `ctrl-f`）搜尋時間線。桌面端可在完成、失敗或等待輸入時發送通知；通知文字有長度限制，不含完整訊息或終端機輸出。

## 行動端操作

配對後，行動端可以查看同一時間線、傳送後續訊息、回答問題與處理允許的核准。它不在本機啟動 Agent，也不持有工作區檔案；斷線後會重新驗證並先 catch-up，再接收即時事件。出現 `resync_required` 時，以桌面端重新同步的時間線為準。
