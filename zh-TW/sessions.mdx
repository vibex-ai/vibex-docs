title: "Agent 會話"
description: "建立、觀察、控制、分叉和恢復 Vibex Agent 會話。"
---

會話把一次開發任務的輸入、Agent 輸出和工具操作儲存為結構化時間線。**權威執行階段**儲存權威時間線，其它客戶端只顯示它的投影。

## 建立會話

1. 選擇目標專案和位置（**本地**、**新建 Worktree**，或 **臨時會話**，見[專案與工作區](/zh-TW/workspaces)）。
2. 在工作區列末端選擇 **傳輸方式**：**Vibex 介面**（預設，由 Vibex 繪製 GUI 時間線）或 **原生終端**（由 Agent 自己的 CLI 在 PTY 裡承載對話）。詳見[終端模式](#終端模式)。
3. 在輸入框頂部選擇 Agent、供應商設定、模型、**思考深度**、**對話模式** 和本會話可用的內建工具。
4. 輸入任務。用 `/` 選命令或 Prompt，用 `@` 引用工作區檔案或 Agent，用 `$` 插入 Skill，或用 `↑` / `↓` 翻出這個會話早先發過的訊息；也可以新增附件。
5. 傳送前確認工作區和權限範圍。Agent 可能需要讀取檔案、執行終端機命令或請求額外授權。

切換 Agent 或模型隻影響後續執行。已寫入時間線的訊息會保留其原始執行身份。

<Note>
  **臨時會話**不屬於任何專案，適合一次性問題或試跑。它仍然由同一個執行階段儲存，也可以歸檔；需要檔案訪問時再選擇專案。側欄、右鍵選單、新建會話選擇器和搜尋裡都把它顯示為「臨時會話」，預設圖示是解析出來的綠色星光。
</Note>

## 終端模式

終端模式把會話交給 Agent 自己的命令列介面：對話在原生 PTY 裡進行，Vibex 不再繪製時間線。它適合已經習慣某個 Agent 的 TUI、或者需要該 CLI 獨有能力的時候。

| | **Vibex 介面** | **原生終端** |
| --- | --- | --- |
| 誰繪製對話 | Vibex 時間線 | Agent 自己的 CLI |
| Vibex 擴充（目標、委派、核准卡、佇列、定時傳送、用量） | 支援 | 不支援 |
| 會話列、搜尋、通知、行動端、TUI | 支援 | 支援，仍在同一列上 |
| 憑證來源 | 供應商設定或 Agent 帳號 | 只能來自**供應商設定** |

已驗證十三個 Agent CLI：Claude、Codex、OpenCode、Gemini、Pi、Grok、Cline、Copilot、Cursor、Kimi、CodeBuddy、Devin 和 Hermes。沒有終端模式的 Agent 完全不顯示這個開關。

運作方式：

- 新建會話頁的草稿作為位置參數交給 CLI，附件以路徑跟隨，因此 Agent 從你已經描述過的那一輪開始。
- 設定的模型隨命令列傳入；選的是 Agent 預設值時什麼也不傳，而不是猜一個 id。
- 終端模式只攜帶**供應商設定**。頁面沒有可交出的設定時，開關的提示會說明 CLI 會用它自己的登入狀態。
- 會話列仍會回報 Agent 的活動、未讀狀態和通知，這些來自 Vibex 在終端網格之外記錄的觀測事實；讀不到時狀態是「未知」，而不是猜成閒置。
- 程序結束後會話會被關閉並標記為錯誤；重啟會重新提供同一份 argv、工作目錄和供應商設定，並從記錄的 argv 重建 PTY。
- MCP 伺服器、Vibex 委派、內嵌瀏覽器和電腦操作透過每個 CLI 真正讀取的啟動輸入投遞，憑證不進入命令列。沒有按程序傳入 MCP 入口的 Agent（Cursor、Gemini、Grok、Kimi Code、Devin）會把兩個工具面板顯示為不可用。

<Warning>
  終端模式沒有 Vibex 的核准卡。Agent CLI 自己的權限提示直接在終端裡回答，Vibex 不會替你確認。停止會話也不會撤銷已經完成的外部操作。
</Warning>

## 閱讀時間線

| 專案 | 你會看到什麼 |
| --- | --- |
| 使用者與 Agent 訊息 | Markdown 文本、圖片和附件。 |
| 推理 | Agent 的推理摘要，可用 **展開推理過程** / **收起推理過程** 展開或收起。 |
| Plan | 待辦步驟及其進度。 |
| 工具與程序詳情 | 工具名稱、引數摘要、程序和退出結果，以及 **{n} process events** 計數。 |
| 權限請求 | 等待你批准或拒絕的操作。 |
| 詢問表單 | Agent 需要你填寫的型別化表單。 |
| 委派 | 子 Agent 或委派任務的狀態和結果。 |
| 目標 | 目標階段、統計和控制按鈕。 |
| 狀態事件 | 執行、排隊、等待、完成、失敗、停止和重連。 |

回合上方會顯示 **工作了** 的耗時。生成過程中會顯示 **思考中...** 或 **等待確認中...**。已結束的回合可以摺疊；對話流只讀取有界視窗，向上翻頁會載入更早的歷史而不移動你當前的位置。

在使用者訊息、Agent 回答、選區、過程列、回合標題或時間線上按右鍵可以開啟選單：複製、引用到輸入框、在該列分叉、編輯並重發、停止正在串流輸出的回答，或複製過程列的指令、輸出、輸入、diff 和路徑。選區可以按文字或 Markdown 複製、引用、尋找並開啟一個外部連結。列內選區優先於該列的選單；在分組面板或唯讀的子 Agent 側欄上開啟的選單作用於那份轉錄，子 Agent 側欄只保留複製和引用。

**設定 → 會話** 裡的 **自動摺疊工具呼叫** 預設關閉。啟用後，進行中的工具活動只畫一行摘要——改動檔案、命令、讀取和失敗的數量——展開後才顯示具體呼叫；含待核准列的執行保持即時展開。

工具引數、終端機輸出和檔案差異可能包含敏感內容。分享診斷前先檢查並脫敏。

## 會話組與分屏

會話組把同一 Worktree 下的多個會話放在一起，適合一個任務下的多個 Agent 或分支：

- 在側欄多選會話，右鍵選擇 **新建會話組**。
- 組內可以 **分屏** 並排檢視，或 **合併窗格** 回到單檢視。
- 組頭顯示團隊狀態：執行中、等待核准、完成或失敗。
- 可以對整組開啟 **自動繼續**，讓滿足條件的會話一起推進。
- 組可以拖動到資料夾、與其他組換位，或拖回工作區根；組內成員可以重排，拖到組外就移出組。
- **解散會話組** 不會刪除會話。

會話組只能包含同一個 Worktree 下的會話。需要跨 Worktree 並行時，用多個組。

## 目標

支援目標的 Agent 會通過 ACP 釋出目標狀態：通用的 `_meta.goal` 擴充套件，以及 Codex 舊的 `_meta.codex.goal` 名稱空間。Vibex 把這些歸一成同一套模型，並把每次變化存成一條目標時間線條目。

目標顯示在輸入框上方的固定目標欄裡，緊接在排隊訊息欄下面：

- 目標欄顯示階段、目標和 Agent 自己上報的統計（已用時間、token 用量、回合數）。
- 鉛筆按鈕（**編輯目標**）開啟原地編輯器改寫目標；儲存時通過目標控制下發，不經過輸入框。
- **暫停目標** / **繼續目標** 暫停或繼續目標。
- **清除目標** 清除目標；進行中、已暫停、已阻塞和額度受限的目標都能清除。

只有介面卡明確宣告支援時，對應的按鈕才會出現。以 `/goal` 發出的訊息保留自己的氣泡，並在氣泡邊緣帶一個目標圖示。

## 委派與 Agent 團隊

委派不再是一問一答。被委派的任務有生命週期：

- **保持開啟**：回合結束後，子會話仍然存在，可以繼續追加跟進。
- **接受**：確認結果，任務結束；重試會落到最初那次接受，不會覆蓋早先的工作。
- **取消**：永久取消，阻止該任務名下任何位置的新訊息和新子工作。
- **跟進**：只有真正執行過的任務才能繼續；意圖變了會被拒絕。

介面上可以看到：

- 側欄的 **所有權樹**：父會話下掛委派出的子會話，用樹形導軌連線。
- 會話組的 **團隊狀態頭**：顯示有多少子 Agent 在執行、等待或完成。
- **委派卡片**：定位到子會話所在的窗格。
- `@` 引用選單分成 **檔案** 和 **Agent 委派** 兩個標籤頁，每行會說明自己指的是檔案還是 Agent。

子 Agent 有獨立時間線，可以從右側欄的 **子 Agent 時間線** 進入。子 Agent 生成的標題不會覆蓋根會話標題。

## 控制執行

| 操作 | 說明 |
| --- | --- |
| **停止當前回覆** | 停止當前執行。已寫入的檔案或已執行的命令**不會**自動回滾。 |
| **繼續** | 在同一會話中繼續傳送任務。 |
| **重試** | 按 Agent 支援的重試語義重新執行失敗回合；不確定是否已執行的外部操作應先檢查結果。 |
| **分叉會話** | 從當前時間線或側欄行建立分支會話，適合比較兩種實現。 |
| **重新命名** | 修改會話標題，不會改變 Agent 上下文。 |
| **編輯訊息** | 改寫最後一條使用者訊息；已完成的時間線事件不會被改寫。 |
| **歸檔** | 把會話移出側欄，保留完整時間線；可以從 **設定 → 已歸檔會話** 恢復。 |

<Warning>
  停止 Agent 只停止執行過程，不會撤銷檔案、Git 或外部服務變更。請在 Git diff 和終端機中分別檢查結果。
</Warning>

## 訊息佇列、引導與定時傳送

執行期間傳送的後續訊息會進入佇列。輸入框上的佇列區域提供：

- **自動傳送** / **手動傳送** —— 切換自動或手動提交佇列。
- **引導** —— 只對聲明瞭原生引導（native steering）的 Agent 出現：它把這條訊息注入正在執行的回合，而不是先打斷。其它 Agent 仍然回退為打斷並重發。
- **定時傳送** —— 給訊息選一個整點，它留在佇列裡等待；跨重啟保留，在彈出面板裡編輯，也能看到另一個客戶端正在持有的傳送。
- **傳送排隊訊息**、**編輯排隊訊息**、**刪除排隊訊息** —— 逐項操作。
- **恢復佇列傳送** / **清空排隊訊息** —— 整體恢復或清空。

投遞方式會記在使用者訊息上，並渲染成氣泡下邊緣的反應標記：**已引導執行中的回合**（主色）或 **已打斷上一輪並重新發送**（警告色）。當後面已經存在更新的回合時，舊回合會標記為被取代：即時狀態、執行階段長和流式行擴充套件停止，但已經產生的行仍然可見並保持展開。

取消或刪除佇列項不會撤銷已經完成的操作。定時傳送到點後仍受會話狀態和權限約束；如果會話在等待核准，傳送會等待而不是跳過核准。

## 自動繼續

啟用 **自動繼續** 後，只有滿足會話設定和 Agent 能力的回合會自動推進。遇到權限請求、詢問表單、失敗或需要使用者選擇時會停下來等待。

- 自動繼續預設開啟，可以在 **設定 → 會話** 裡改預設值。
- 會話組可以單獨開啟整組自動繼續。
- 倒計時期間可以按 TUI 的 `t` 或點選介面上的停止按鈕取消本次自動繼續。
- 自動繼續不會繞過權限核准，也不會替你回答詢問表單。

## 權限請求與詢問表單

當 Agent 請求終端機、檔案寫入、瀏覽器導航、電腦操作或其他受保護能力時，時間線會顯示請求原因和範圍，通常包含工作目錄、引數和環境變數。可選操作為 **允許**、**拒絕** 和 **本會話始終允許**。

詢問表單需要填寫結構化內容。提交前確認值和作用範圍；取消表單會讓 Agent 收到取消結果，而不是隱式批准。

電腦操作的核准卡還會顯示目標應用、操作類別和原因；破壞性或前臺操作附帶目標視窗截圖。密碼管理器、安全輸入框和 Vibex 自身視窗始終逐次處理或直接拒絕。

## 全域性搜尋與查詢

`cmd-k` 在任何位置都能開啟 **全域性搜尋**（工作台命令面板），入口是標題欄裡的搜尋圖示，緊挨執行階段控制元件之前。一次輸入同時檢索三組結果：

| 分組 | 範圍 | 選中後 |
| --- | --- | --- |
| **最近會話** / **會話** | 會話標題和訊息正文 | 開啟會話並跳到命中的那條訊息 |
| **設定** | 設定項 | 開啟設定、定位到對應分區並高亮那一行 |
| **快捷操作** | 註冊在工作台上的真實 Action | 直接執行；每行顯示自己的快捷鍵，前置條件不滿足時顯示為不可用 |

- 面板頂部有自己的查詢框，三組之間畫有分隔線；空查詢時只列出 **最近會話**。
- 會話搜尋只索引和高亮對話文本——使用者訊息、Agent 回答、推理和計劃——並只給命中的關鍵詞著色，當前命中顏色更重。
- 輸入非空時按 `escape` 先清空輸入，再按一次才關閉。
- 索引在後臺構建並保留，再次開啟是瞬間完成的。已歸檔的會話不參與搜尋。

單會話內的查詢仍然用 `cmd-f`（**在當前會話中查詢**）。

## 匯入本地歷史

通過側欄 **更多** 選單或專案右鍵選單中的 **匯入會話** 匯入其它 Agent 的歷史。

支援 14 個來源：**Claude Code**、**Codex**、**OpenCode**、**Gemini CLI**、**Cline**、**Hermes**、**CodeBuddy Code**、**Kimi Code**、**Pi**、**Grok**、**Cursor**、**DeepSeek Harness**、**ZCode**、**Google Antigravity**。

流程：

1. Vibex 掃描本機歷史，顯示 **正在掃描本地 Agent 會話...**。
2. 在預覽列表中按專案分組勾選要匯入的會話，可以按 Agent 篩選或重新掃描。
3. 點選 **匯入 {n} 個會話**，等待 **匯入完成**。

結果會分成 **已匯入**、**已消失**、**失敗** 等類別。

<Note>
  掃描器只讀取後設資料：標題、時間、工作區路徑、訊息數量和來源路徑。匯入時才會重新讀取內容並一次性寫入時間線。憑據、金鑰和完整 Agent home 配置**不會**匯入。已匯入過的會話不會重複匯入，也不會被重新整理覆蓋。
</Note>

## 通知與未讀

會話完成、失敗或等待輸入時，權威執行階段可以傳送桌面通知。三類通知可以在 **設定 → 會話** 的 **Agent 通知** 中分別開關。

有未讀完成項的會話在側欄顯示圓點提示；開啟會話後提示消失，以權威時間線為準。系統托盤選單也提供 **新建會話**、**配置中心** 和 **設定** 的快捷入口。

## 歸檔與恢復

歸檔會保留完整時間線，只把會話移出側欄：

- 從會話行選單、多選選單或批次欄都可以歸檔；歸檔是可逆的，所以不彈確認。
- **設定 → 已歸檔會話** 可以恢復或永久刪除。
- 自動歸檔可以按專案/資料夾設定空閒視窗（關閉，或 1–14 天）。
- 誤歸檔可以撤銷；刪除不能。

## 子 Agent 時間線

當會話使用了委派時，右側欄會出現 **子 Agent 時間線** 入口，可以檢視子 Agent 的獨立時間線，並從父會話跳轉過去。子 Agent 的更新會標記歸屬，不會混進父會話的行。

## 在終端機裡繼續

Vibex TUI 可以附著到同一個執行階段，讀取同一批會話、傳送訊息、處理核准和佇列。`vibex` 會開啟當前目錄的新會話頁；`Ctrl+L` 開啟會話列表。詳見 [Vibex TUI](/zh-TW/tui)。
