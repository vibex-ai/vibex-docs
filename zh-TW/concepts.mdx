這一頁解釋 Vibex 裡反覆出現的幾個詞。讀完它，其它頁面會好懂很多。

## 權威執行階段（runtime）

**權威執行階段**是唯一持有真實狀態的東西：Agent 程序、會話時間線、工作區檔案、Git 倉庫、終端機、瀏覽器、電腦操作、供應商憑據和本地資料庫。所有客戶端都只是它的投影檢視。

Vibex 裡存在三種權威執行階段形態，它們共用同一套核心，能力基本一致：

| 形態 | 說明 |
| --- | --- |
| **桌面端內嵌執行階段** | 預設。隨桌面應用一起啟動，資料存在本機。 |
| **無頭執行階段 `vibex-server`** | 獨立守護程序，跑在你自己的伺服器或常開機器上。 |
| **SSH / WSL 遠端執行階段** | 桌面端通過 SSH 在另一臺機器上配置 `vibex-server`，或在本機 WSL2 裡執行它（測試版）。 |

桌面工作台、行動端和 TUI 都是**客戶端**。桌面端預設使用自己的內嵌執行階段；你也可以把它切換成連線某個遠端執行階段，此時它和手機、TUI 一樣只是客戶端。切換入口在標題欄的 **執行階段** 按鈕。

## 專案（project）

**專案**是你在 Vibex 裡註冊的一個資料夾：有名字、有圖示、在側欄里長期存在。側欄的 **專案** 列表就是它，右鍵選單裡有改名、定製圖示、新建資料夾、匯入會話和刪除等操作。

一個專案下面可以有**多個工作區**。

## 工作區（workspace）

**工作區**是“以某種方式使用這個專案”。目前有三種位置：

| 模式 | UI 上的叫法 | 行為 |
| --- | --- | --- |
| `CurrentCheckout` | **本地** / 當前檢出 | 直接在主檢出目錄上工作。 |
| `VibexWorktree` | **Worktree** | Vibex 建立一個託管 Git worktree，把改動隔離在獨立目錄裡。 |
| 臨時 | **臨時會話** | 不屬於任何專案，適合一次性任務；不能建立 Worktree。 |

同一個專案下可以同時存在一個 `Local` 工作區和多個 `Worktree` 工作區。這就是為什麼可以一邊在主分支上幹活，一邊讓 Agent 在隔離目錄裡試另一個方案。

會話總是屬於某一個具體的工作區（或臨時空間）。切換工作區不會把未提交改動帶過去。

詳見[專案與工作區](/zh-TW/workspaces)。

## 會話（session）

**會話**是一次開發任務的完整記錄：你的輸入、Agent 的輸出、工具呼叫、核准和錯誤，按時間順序儲存為**時間線**。會話歸屬於它建立時所在的工作區。

側欄的 **新建會話** 建立新會話。會話可以重新命名、置頂、分叉、歸檔、批次刪除，也可以從其它 Agent 的歷史裡匯入。多個會話可以組成**會話組**，在同一 Worktree 下分屏檢視。

會話裡的委派會產生**子會話**，它們掛在父會話的所有權樹下，有獨立時間線。詳見[Agent 會話](/zh-TW/sessions)。

## Agent 與供應商

這幾個概念經常被混在一起：

| 概念 | 回答的問題 | 在哪裡配置 |
| --- | --- | --- |
| **Agent** | 誰來做？ | 配置中心 → Agent |
| **模型供應商設定** | 這個 Agent 用哪個地址、憑據、模型和思考檔位？ | 配置中心 → Agent → 詳情 |
| **共享供應商（Provider）** | 一套地址、Key 和模型，能被哪些 Agent 和路由組使用？ | 配置中心 → 供應商 |
| **路由組** | 多個 Provider 或模型如何排序、失敗轉移？ | 配置中心 → 供應商 → 路由組 |
| **本地閘道器** | 路由組請求實際發往哪個迴環端點？ | 配置中心 → 供應商 → 閘道器 |

一個 Agent 可以只用自己的模型供應商設定，也可以繫結共享 Provider 或路由組。切換隻影響後續執行，已有時間線保留原來的執行身份。

詳見[Agent 與供應商設定](/zh-TW/agents-and-providers)和[供應商、路由組與本地閘道器](/zh-TW/providers-and-gateway)。

## 作用域

部分資源可以設定作用範圍。可用取值通常是 **global**、**user**、**project** 或 **workspace**，範圍越小越不容易誤傷其它專案。MCP 伺服器當前只提供 **使用者** 和 **工作區** 兩種。

## 通道（channel）

釋出通道決定產品身份和資料目錄：**預覽**、**RC**、**Stable**。三者可以並存安裝，各自使用獨立的資料庫，互不影響。通道由安裝包決定，不能在應用內切換。

## 配對（pairing）

**配對**是給一臺裝置授予訪問某個權威執行階段的權限。兩種常見路徑：

- **桌面 → 手機 / TUI**：桌面端生成二維碼或連結，手機掃碼、TUI 用 `vibex connect` 認領。
- **伺服器 → 桌面 / 手機 / TUI**：`vibex-server` 列印一次性配對碼和連線串，客戶端填入。

配對時選擇的**權限級別**決定該裝置能做什麼：`read_only`、`approve_only`、`full_control`。級別在發起端決定，客戶端無法自行提權。

詳見[遠端訪問與行動端](/zh-TW/remote-mobile)。
