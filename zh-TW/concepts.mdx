這一頁說明 Vibex 裡反覆出現的幾個詞。讀完它，其他頁面會好懂很多。

## 權威執行環境（runtime）

**權威執行環境**是唯一持有真實狀態的東西：Agent 程序、會話時間線、工作區檔案、Git 儲存庫、終端機、供應商憑證和本機資料庫。所有客戶端都只是它的投影檢視。

Vibex 裡存在兩種權威執行環境形態，它們共用同一套核心，能力一致：

| 形態 | 說明 |
| --- | --- |
| **桌面端內嵌執行環境** | 預設。隨桌面應用程式一起啟動，資料存在本機。 |
| **無頭執行環境 `vibex-server`** | 獨立常駐程序，跑在你自己的伺服器或常開機器上。 |

桌面工作台和行動端都是**客戶端**。桌面端預設使用自己的內嵌執行環境；你也可以把它切換成連線某個遠端執行環境，此時它和手機一樣只是客戶端。切換入口在標題列的 **Runtime** 按鈕。

## 專案（project）

**專案**是你在 Vibex 裡註冊的一個資料夾：有名稱、有圖示、在側欄裡長期存在。側欄的 **Projects** 清單就是它，右鍵選單裡有重新命名、自訂圖示、刪除等操作。

一個專案下面可以有多個**工作區**。

## 工作區（workspace）

**工作區**是「以某種方式使用這個專案」。目前有兩種模式：

| 模式 | UI 上的叫法 | 行為 |
| --- | --- | --- |
| `CurrentCheckout` | **Local** / 目前檢出 | 直接在主檢出目錄上工作。 |
| `VibexWorktree` | **Worktree** | Vibex 建立一個受管理 Git worktree，把變更隔離在獨立目錄裡。 |

同一個專案下可以同時存在一個 `Local` 工作區和一個或多個 `Worktree` 工作區。這就是為什麼可以一邊在主分支上工作，一邊讓 Agent 在隔離目錄裡試另一個方案。

會話總是屬於某一個具體的工作區。切換工作區不會把未提交變更帶過去。

詳見[工作區](/zh-TW/workspaces)。

## 會話（session）

**會話**是一次開發任務的完整記錄：你的輸入、Agent 的輸出、工具呼叫、核准和錯誤，依時間順序儲存為**時間線**。會話歸屬於它建立時所在的工作區。

側欄的 **New chat** 建立新會話。會話可以重新命名、置頂、分叉、批次刪除，也可以從其他 Agent 的歷史裡匯入。

詳見[Agent 會話](/zh-TW/sessions)。

## Agent 與供應商設定

這兩個概念是分開的：

- **Agent** 是執行任務的程式，例如 Claude Code、Codex、ZCode、OpenCode，或任何相容 ACP 的可執行檔。Agent 決定「誰來做」。
- **供應商設定**（UI 裡叫 **Model provider configuration**）是 Agent 呼叫模型服務所需的連線資訊：位址、憑證、可用模型、思考深度。它決定「用哪個模型、走哪條線路」。

同一個 Agent 可以設定多套供應商設定，並在傳送訊息前切換。切換只影響後續執行，已有時間線保留原來的執行身份。

詳見 [Agents 與供應商設定](/zh-TW/agents-and-providers)。

## 作用域

部分資源可以設定作用範圍。可用取值通常是 **global**、**user**、**project** 或 **workspace**，範圍越小越不容易誤傷其他專案。MCP 伺服器目前只提供 **User** 和 **Workspace** 兩種。

## 通道（channel）

發佈通道決定產品身份和資料目錄：**Preview**、**RC**、**Stable**。三者可以並存安裝，各自使用獨立的資料庫，互不影響。通道由安裝套件決定，不能在應用程式內切換。

## 配對（pairing）

**配對**是給一台裝置授予存取某個權威執行環境的權限。兩種常見路徑：

- **桌面端 → 手機**：桌面端產生 QR Code，手機掃碼並核對驗證碼。
- **伺服器 → 桌面端 / 手機**：`vibex-server` 印出一次性配對碼和連線字串，客戶端填入。

配對時選擇的**權限等級**決定該裝置能做什麼：`read_only`、`approve_only`、`full_control`。等級在發起端決定，客戶端無法自行提權。

詳見[遠端存取與行動端](/zh-TW/remote-mobile)。
