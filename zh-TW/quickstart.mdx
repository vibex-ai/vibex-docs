title: "快速開始"
description: "安裝 Vibex，連上一個 Agent，完成第一次會話。"
---

這篇指南帶你安裝桌面端、新增一個 Agent、開啟專案目錄，然後讓 Agent 完成一個可檢查的小任務。首次嘗試建議使用一個可丟棄的 Git 倉庫。

## 1. 安裝桌面端

從 [GitHub Releases](https://github.com/vibex-ai/vibex/releases/latest) 下載與你平台匹配的安裝包並安裝。完整說明和各平台注意事項見[安裝](/zh-TW/install)。

<Note>
  macOS 和 Windows 的安裝包沒有 Developer ID 簽名或公證，首次開啟會遇到 Gatekeeper 或 SmartScreen 的提示。放行方法見[安裝](/zh-TW/install)。
</Note>

## 2. 新增一個 Agent

第一次啟動時，Vibex 會顯示 **開始新的工作** 頁面。沒有可用 Agent 時會提示 **尚未新增 Agent，請進入配置中心新增。**，點選 **新增 Agent** 進入配置中心。

1. 在 **Agent** 標籤頁的列表中找到你想用的 Agent。內建預設包括 **Claude Code**、**Codex**、**ZCode** 和 **OpenCode**，另有十多個 ACP 整合。
2. 點選條目右側的 **+** 把它加入。加入後條目會顯示啟用開關。
3. 如果該 Agent 由 Vibex 託管且尚未安裝，安裝卡片會顯示 **安裝**。點選後 Vibex 會下載並校驗執行階段；安裝過程中不能取消，裝好後按鈕變為 **檢查更新**。
4. 如果條目顯示 **由使用者管理**，說明它不在託管目錄裡，Vibex 會直接使用你 `PATH` 上的同名命令列程式——你需要先自己裝好它。

接著展開詳情頁裡的 **原生憑證** 卡片完成登入（`Sign in` / `Open sign-in terminal`），或在 **模型供應商設定** 卡片裡新增一套自己的地址、Key 和模型。

<Note>
  一個 Agent 可以有多套模型供應商設定；共享 Provider 和路由組在 **配置中心 → 供應商** 裡，見[供應商、路由組與本地閘道器](/zh-TW/providers-and-gateway)。
</Note>

## 3. 開啟一個專案目錄

1. 在側欄點選 **新建專案**，或使用 **新建會話** 頁面上的 **專案目錄**。
2. 在彈出的目錄瀏覽器裡選擇倉庫根目錄，確認。
3. 首次嘗試請使用測試分支或臨時倉庫——Agent 會真實修改磁碟上的檔案。

也可以選擇 **臨時會話**，不繫結專案，先試一條提示詞。

## 4. 完成第一次會話

1. 在輸入框頂部選擇 Agent、供應商設定、模型和**思考深度**。
2. 輸入一個範圍明確的任務，例如“在 `README.md` 中補充安裝步驟，並先展示計劃”。
3. 檢視時間線中的計劃和工具呼叫。需要檔案、終端機或權限時，Vibex 會顯示具體請求，你可以 **允許** 或 **拒絕**。
4. Agent 完成後開啟 **Git** 面板檢查 **變更**，逐處確認改動，再決定是否提交或繼續追問。

<Tip>
  第一次任務先要求 Agent 給出計劃，再允許它修改檔案。這樣你能在時間線裡確認範圍和風險。
</Tip>

<Warning>
  **停止** 只停止執行，不會回滾已經寫入的檔案或已經執行的命令。停止後請在 Git diff 和終端機裡分別確認結果。
</Warning>

## 瞭解輸入框

在輸入框中可以組合多種上下文：

| 寫法 | 作用 |
| --- | --- |
| `/` | 選擇可用的 Prompt 或 slash command。 |
| `@` | 從當前專案引用檔案或目錄，或引用一個 Agent 委派。 |
| `$` | 插入已啟用的 Skill。 |
| 附件按鈕 | 新增圖片等會話附件。 |

傳送前可以選擇 Agent、供應商設定、模型、思考深度、對話模式和本會話可用的內建工具。不同 Agent 支援的選項不同，介面會根據執行階段探測結果顯示可用項。

執行中傳送的訊息會進入佇列。可以編輯、刪除、引導執行中的回合，或給訊息選一個整點稍後傳送。

## 5. 試試終端機客戶端

TUI 隨桌面安裝包一起釋出。在專案目錄裡執行：

```bash
vibex
```

它會附著到同一個執行階段；`vibex status` 可以檢視它會用哪個執行階段。詳見 [Vibex TUI](/zh-TW/tui)。
