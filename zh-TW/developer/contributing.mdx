## 開始前

1. 閱讀根目錄 `README.md` 與相關 `docs/` 設計/檢查說明。
2. 搜尋既有 facade、DTO、reducer 和平台適配器，再決定是否需要新抽象。
3. 保留工作樹中已有的未提交變更，不覆蓋其他人的檔案。

## 實作原則

- 保持 `DesktopRuntime` 為唯一權威狀態所有者。
- 讓行動端透過共享後端與 Remote v2 契約存取能力。
- 使用結構化錯誤、能力和序號，不依賴 UI 文案判斷成功。
- 對檔案、Git、終端機、Provider 和裝置操作執行權限校驗與審計。
- 日誌、測試證據與診斷資料脫敏，不寫入 secret、Prompt、檔案內容或終端機位元組。

## 提交前檢查

```bash
pnpm check
pnpm release:build-smoke
pnpm check:mobile-native
```

依改動範圍補充 `check:acp`、`check:code-workbench`、`check:terminal`、`smoke:relay:local` 或 Cargo 測試。跨層變更應覆蓋斷線、重啟、權限不足、序號間隙和恢復路徑。

## 文件與證據

使用者可見行為要同步更新簡體中文、繁體中文和英文頁面。未確認細節用 `TODO` 標記，不把測試 spike 當成穩定功能。使用文字步驟、狀態表、協議欄位和脫敏診斷記錄說明行為；不要要求視覺擷取，也不要提交工作區內容作為證據。

## Pull Request

PR 說明行為變更、所有權邊界、測試命令、相容性、遷移、回滾策略和已知限制。入口見 [GitHub](https://github.com/vibex-ai/vibex)。
