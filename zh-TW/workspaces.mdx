---
title: "專案與工作區"
description: "選擇、切換和隔離 Vibex 的檔案、Git 與 Agent 工作範圍。"
---

**專案**是你在 Vibex 裡註冊的一個資料夾；**工作區**是「以某種方式使用這個專案」。一個專案下可以同時存在多個工作區。

工作區是 Vibex 讀寫檔案、執行終端機和進行 Git 操作的邊界。權威執行環境儲存工作區中繼資料和目前選擇；Agent 能看到的檔案範圍也由工作區決定。

## 階層關係

```text
專案（Project）
├── 工作區 Local（CurrentCheckout）    ← 直接在主檢出目錄工作
└── 工作區 Worktree（VibexWorktree）   ← 隔離目錄，可並存多個
        └── 會話（Session）
```

也就是說：**worktree 不是「另一種模式」，而是同一個專案下的第二個工作區。** 這正是可以一邊在主分支工作、一邊讓 Agent 在隔離目錄裡試另一個方案的原因。

## 兩種工作區模式

| 模式 | UI 上的叫法 | 行為 |
| --- | --- | --- |
| `CurrentCheckout` | **Local** / Current checkout | 檔案和 Git 操作直接作用於主檢出目錄；多個會話可能看到同一份變更。 |
| `VibexWorktree` | **Worktree** | Vibex 建立受管理 Git worktree，並提供合併、rebase、衝突處理和丟棄流程。 |

<Warning>
  在 **Local** 工作區裡同時執行多個 Agent 時，它們可能修改同一個檔案。需要並行嘗試或審查時，改用 **Worktree**。
</Warning>

## 開啟專案

1. 在側欄點擊 **New project**，或在 **New chat** 頁面使用 **Project directory**。
2. 在彈出的目錄瀏覽器中選擇儲存庫根目錄（這是一個應用程式內瀏覽器，支援 `↑↓` 導覽、`Enter` 開啟、`⌘Enter` 在此選擇）。
3. 確認後 Vibex 會以 **Local** 模式開啟該目錄。

專案會長期保留在側欄。右鍵點擊專案可以自訂圖示、新增資料夾、開啟 **Auto continue**、匯入會話或刪除專案。

## 在專案下新增工作區

新增會話時，Composer 上方的位置選擇器提供兩個選項：

- **Local** —— 在主檢出目錄上工作。
- **New Worktree** —— 建立隔離工作區。選擇後會出現 **Base ref** 選擇器（可搜尋分支），以及 **Worktree settings** 面板：
  - **Worktree name** —— 會據此推導出分支名稱 `vibex/<slug>`。
  - **Path** —— 必須是絕對路徑。
  - **Default to a new Worktree for this Project** —— 以後該專案預設新增 worktree。

## 切換工作區

側欄的 **Workbench → Sidebar hierarchy** 設為 **Workspace view** 時，專案下會列出各個工作區及其分支。

切換工作區不會把未提交變更複製到另一處。目前會話仍屬於它建立時所在的工作區；切換前請儲存檔案並檢查 Git 狀態。

如果編輯器裡還有未儲存的緩衝區，Vibex 會先阻止切換並提示你儲存或放棄。每次開啟或切換工作區都會更新 generation，過期的檔案、終端機和 Git 請求會被拒絕，避免結果寫入錯誤目錄。

## Worktree 生命週期

| 狀態 | 主要操作 |
| --- | --- |
| **Working** | **Review changes** |
| **Reviewing** | **Mark ready** |
| **Ready** | **Merge** / **Rebase**（對應 `NoFfMerge` 與 `RebaseAndMerge`） |
| **Queued** | **Review merge** |
| **Archived** | 恢復 |

1. 建立時選擇基礎分支和名稱。
2. 在隔離目錄中啟動會話或手動編輯。
3. 用 Git 面板檢查變更，並視需要提交。
4. 選擇 **Merge** 或 **Rebase**。出現衝突時逐檔案處理（可對每個檔案選擇保留目標端或來源端），處理完點擊 **Mark resolved**。中途可以用 **Abort merge** 放棄合併。
5. 確認結果後再丟棄 worktree。**丟棄會刪除隔離目錄和未提交變更。**

也可以對 worktree 執行 **Rename Worktree** 和 **Delete Worktree**。

<Info>
  Worktree 的路徑、分支和狀態由權威執行環境儲存。行動端可以透過 Remote v2 請求這些操作，但實際執行始終發生在權威端。
</Info>

## 檔案存取邊界

- 檔案樹、內容搜尋和編輯器只存取目前工作區範圍。
- 檔案服務會規範化路徑並檢查符號連結、編碼、換行符號和大小限制。
- Agent 的工具呼叫仍受權限和能力控管影響——開啟工作區不等於自動授權所有操作。
- 終端機預設綁定目前工作區，也可以在檔案樹裡對某個路徑選擇 **Open In → Terminal**。
- 遠端請求還會攜帶工作區作用域和 generation；重連後以權威執行環境重新讀取的狀態為準。

## 常見問題

### 為什麼 Agent 看不到我剛建立的檔案？

確認檔案儲存到了目前工作區，並重新整理檔案樹或重新開啟會話。如果檔案在工作區之外，需要先移動到工作區內，或作為附件提供。

### 為什麼 Git diff 沒有顯示變更？

檢查是否切換到了另一個工作區或 worktree——`Local` 和 `Worktree` 是完全不同的目錄。確認檔案已儲存，再在終端機裡執行 `git status --short` 對照。
