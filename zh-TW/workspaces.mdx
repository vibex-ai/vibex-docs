工作區是 Vibex 讀寫檔案、執行終端機與進行 Git 操作的邊界。桌面端會保存工作區中繼資料與目前選擇；Agent 看到的檔案範圍也由工作區決定。

## 兩種工作區模式

| 模式 | 適用情境 | 行為 |
| --- | --- | --- |
| **CurrentCheckout** | 直接在目前檢出的分支上工作。 | 檔案與 Git 操作作用於目前目錄；多個會話可能看見相同變更。 |
| **VibexWorktree** | 將 Agent 變更與主檢出隔離。 | Vibex 建立受管理 Git worktree，提供合併、rebase、衝突處理和丟棄流程。 |

<Warning>
  在 **CurrentCheckout** 中同時執行多個 Agent 時，它們可能修改同一個檔案。要並行嘗試或評審時，優先選擇 **VibexWorktree**。
</Warning>

## 開啟或切換工作區

1. 在側欄開啟工作區選擇器。
2. 選擇現有儲存庫目錄，或建立受管理 worktree。
3. 確認工作區根目錄與 Git 分支。
4. 開啟檔案、終端機或會話時，檢查頂端顯示的目前工作區。

切換工作區不會把未提交變更複製到另一處。切換前請儲存檔案並檢查 Git 狀態。

## 受管理 worktree 生命週期

1. 建立 worktree 時選擇基礎分支與名稱。
2. 在隔離目錄中啟動會話或手動編輯。
3. 使用 **Git diff** 檢查變更，並視需要提交。
4. 選擇合併或 rebase。發生衝突時，Vibex 保留可恢復狀態並列出待處理檔案。
5. 確認主工作區結果後再丟棄 worktree；丟棄會刪除隔離目錄與未提交變更。

<Info>
  worktree 的路徑、分支和狀態由桌面端保存。行動端只能透過遠端權限請求這些操作，不能自行建立本機 worktree。
</Info>

## 檔案存取邊界

- 檔案樹、內容搜尋和編輯器只存取目前工作區範圍。
- 符號連結、編碼、換行與大型檔案會經過檔案服務限制與校驗。
- Agent 工具呼叫仍受權限與能力門控；開啟工作區不代表自動授權所有操作。
- 終端機預設綁定目前工作區，但可以在分頁中切換工作目錄。

## 常見問題

### 為什麼 Agent 看不到我剛建立的檔案？

確認檔案儲存到目前工作區，然後重新整理檔案樹或重新開啟會話。若檔案在工作區外，請移入工作區或在允許時用附件提供內容。

### 為什麼 Git diff 沒有顯示變更？

確認沒有切換到另一個工作區或 worktree，確認檔案已儲存，再於終端機執行 `git status --short`。
