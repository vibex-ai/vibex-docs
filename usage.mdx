title: "用量统计"
description: "按时间、Agent、项目、供应商和模型查看本地用量。"
---

**Usage Statistics** 用来查看 Vibex 已记录的 Agent 用量。它是观测工具，**不是账单页面**——实际价格、额度和发票仍由供应商决定。Vibex 不记录费用，也没有价格字段。

入口：侧栏的 **Usage Statistics** 按钮，或 Composer 上的 token 圆环（**Open usage statistics**）。

## 选择时间范围

工具栏提供四个范围，并据此自动决定分桶粒度：

| 范围 | 含义 | 分桶 |
| --- | --- | --- |
| **Today** | 按系统时区查看今天。 | 小时 |
| **7 days** | 最近七天。 | 天 |
| **30 days** | 最近三十天。 | 天 |
| **All** | 本地保留的全部记录。 | 月 |

没有可用记录时页面显示空状态，不会把未知值当成零。

## 筛选和分组

可以组合五个筛选器：**Agent**、**Model provider**、**Model**、**Project**、**Session**。

结果可以按五个维度分组，也就是表格上方的标签：**Time**、**Agent**、**Project**、**Model provider**、**Model**。

<Note>
  **Project** 维度对应侧栏里的项目，一个项目下可能包含多个工作区。**Session 只作为筛选器**，不能作为分组维度。
</Note>

## 读取指标

汇总区显示六个指标：

| 指标 | 含义 |
| --- | --- |
| **Total tokens** | 各类 Token 的合计。 |
| **API requests** | 已观测的 API 请求数；适配器不提供逐请求数据时改为显示 **Turns**。 |
| **Input** / **Output** | 输入与输出 Token。 |
| **Cached read** | 缓存读取 Token。 |
| **Cache hit rate** | 缓存读取相对于可计算分母的比例。 |

分组表的列为：维度名称、**Requests**、**Total**、**Input**、**Output**、**Cache**、**Hit rate**、**Last activity**、**Coverage**。

### Coverage 的含义

**Coverage** 说明这一行的数据可信到什么程度：

| 显示 | 含义 |
| --- | --- |
| **Reported** | 适配器完整上报。 |
| **Derived from input + output** | 总量由输入加输出推导，而非直接上报。 |
| **Partial** | 只上报了一部分。 |
| **Not reported** | 没有数据。 |

鼠标悬停还可以看到更细的分布（complete / partial / baseline only / unreported / unsupported）。

<Warning>
  **不要把 `Not reported` 或 `Partial` 解读为零**，也不要用它推算供应商账单。缺少供应商字段时 Vibex 会保留未知状态，而不是填充猜测值。
</Warning>

## 趋势视图

| 视图 | 说明 |
| --- | --- |
| **Trend** | 堆叠柱状图，可在 **Total** / **Input** / **Output** / **Cache** 之间切换，图例可点击过滤。 |
| **Heatmap** | 365 天日历热力图，展示每日活动密度；没有年度数据时显示不可用。 |
| **Models** | 按天展示各模型占比（100% 堆叠），取前 10 个模型，其余归入 **Other** 和 **Unknown**。可在 **Turns** 和 **Total tokens** 之间切换。 |

刷新期间页面保留上一份结果并标记为过期；加载失败时优先使用上一份权威结果，并提示 **Refresh failed; showing previous data**。

## 数据边界

- 用量来自权威运行时记录的 Agent 执行和适配器上报。**权威运行时是统计的权威来源。**
- Usage Statistics **不读取**完整提示词、文件内容、终端输出或供应商密钥。
- **移动端不显示用量明细**——移动端的用量页只显示会话数量，并提示 "Usage details are available on the desktop host."
- 单次查询有行数上限（100000 行），超出会返回 `agent_usage_query_too_large`。
