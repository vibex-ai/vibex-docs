Vibex 使用 [Agent Client Protocol](https://agentclientprotocol.com/)（ACP）连接在线 Agent。**Agent**（谁来做）和**模型供应商配置**（用哪个模型、走哪条线路）是分开管理的两件事。

一个 Agent 可以有多套模型供应商配置；一套共享 Provider 也可以被多个 Agent 使用。这一页讲 Agent 自己的配置；共享 Provider、路由组和本地网关见[供应商、路由组与本地网关](/providers-and-gateway)。

## Agent 标签页的结构

打开 **配置中心 → Agent** 后，左侧是 Agent 列表，右侧是所选 Agent 的详情区。详情区从上到下包含：

| 卡片 | 作用 |
| --- | --- |
| **Agent 安装** | 查看安装状态，安装 / 升级 / 回滚 / 卸载托管运行时。 |
| **原生凭证** | 登录 Agent 自己的账号。 |
| **模型供应商配置** | 为该 Agent 配置模型供应商、模型和凭据。 |
| **内置工具** | 按 Agent 开关终端、浏览器、电脑操作等工具面板。 |

<Note>
  模型供应商**不是**独立主分区。每个 Agent 的模型供应商配置挂在 Agent 详情里；共享 Provider 和路由组在 **供应商** 分区里。
</Note>

## 添加 Agent

左侧列表按状态分组：已启用、已添加但停用、尚未添加。每个条目右侧的动作取决于当前状态：

| 状态 | 可做的操作 |
| --- | --- |
| **未添加** | 点击 **+** 加入。 |
| **未安装** | 点击 **安装**，Vibex 会下载并校验托管运行时。 |
| **有可用更新** | 点击 **升级** 升级到新版本。 |
| **可用** | 已就绪，可用启用开关控制它是否出现在会话的 Agent 选择器里。 |
| **由用户管理** | 该 Agent 不在托管目录中，Vibex 会使用你 `PATH` 上的命令行程序。 |
| **已停用** | 已停用，但仍保留配置和会话历史。 |

Vibex 自带四个内建预设：**Claude Code**、**Codex**、**ZCode**、**OpenCode**。ACP 目录另外提供 **Antigravity**、**Cline**、**Codebuddy**、**GitHub Copilot**、**Cursor**、**DeepSeek Harness**、**Devin**、**Gemini CLI**、**Grok Build**、**Hermes**、**Kimi Code**、**Pi** 等集成。

### 托管运行时

- **安装** 会从网络下载并校验运行时；安装过程中不能取消。
- **检查更新** 会读取该 Agent 的发布通道和固定版本。
- **升级** 只移动到兼容的更新版本。
- **回滚** 可以把托管安装退回到 Vibex 为该 Agent 固定的版本；回滚不是“锁定”，之后仍会继续跟踪发布通道。
- **卸载** 会弹出确认对话框，删除托管运行时和缓存版本；会话历史会保留。

<Warning>
  托管安装失败时，先检查网络是否能访问 GitHub 和运行时自己的分发源。不要把完整安装日志或 token 粘贴到公开 Issue。
</Warning>

### 添加自定义 ACP Agent

点击列表底部的 **添加自定义 ACP Agent**，填写：

| 字段 | 说明 |
| --- | --- |
| **Agent ID** | 小写 kebab-case 标识，例如 `my-acp-agent`。 |
| **显示名称** | 显示名称。 |
| **描述** | 可选，说明用途。 |
| **ACP 命令** | 可执行文件、`npx` 或 `uvx` 形式的命令。 |
| **参数** | 以空格分隔的参数。 |
| **环境变量（可选）** | 每行一个 `KEY=value`。 |

自定义 Agent 目前只能新建，不能编辑；关闭开关会删除它，但会话历史保留。

### 内置工具

每个 Agent 的内置工具面板可以在 Agent 列表里开关。启用的工具图标会亮成绿色：

- **终端**：Agent 可以请求运行命令。
- **浏览器**：Agent 可以使用内嵌浏览器工具。
- **电脑操作**：Agent 可以使用桌面操作工具（还需要在设置里安装驱动并开启总开关）。

工具开关只决定 Agent 能不能收到这个工具面，不改变会话里已有的权限审批。关闭工具不会撤销已经执行的操作。

## 登录 Agent 账号

**原生凭证** 卡片管理 Agent 自己的账号，它与外部 CLI 共享同一份凭据——卡片上会明确写出 "Agent-native account · shared with the external Agent CLI"。

- 可用的登录方式由 Agent 决定，常见的有 **登录**、**保存并登录**、**打开登录终端**。
- 卡片提供 **刷新认证方式**、**验证账号**、**刷新模型**、**重新认证**、**退出登录**。
- 重新认证会影响正在使用旧凭据的 Agent 进程；界面会先给出提示。
- **退出登录** 同时影响外部 CLI 和 Vibex 会话，执行前会显示受影响的会话数量。

浏览器授权的登录（Cursor、Grok、Gemini、Cline、CodeBuddy、Antigravity 等）可能不声明退出登录能力；Vibex 会把它们识别为可用的 OAuth 方式，而不是当成不可用。

## 配置模型供应商

在 **模型供应商配置** 卡片中点击 **添加配置**，或对已有配置点击编辑。编辑器分三段：

### 基本信息

| 字段 | 说明 |
| --- | --- |
| **供应商名称** | 必填。显示用名称。 |
| **备注** | 可选备注。 |
| **官网链接** | 可选。 |
| **类型** | 官方、官方 / 中转 / 本机等来源标记。 |

### 连接与凭证

| 字段 | 说明 |
| --- | --- |
| 凭据 | 由所选 Agent 决定用 API Key、OAuth 还是 Agent 账号。 |
| **默认 API 请求地址** | 供应商的 API 地址，例如 `https://provider.example/v1`。部分 Agent 会锁定此项。 |
| **按协议分别设置地址** | 折叠区，需要为不同协议分别指定地址时展开。 |
| **请求头** | 可选。支持字面值和内置 `session_id` 变量。 |
| **代理** | 直连、系统代理或自定义代理地址。 |

API Key 输入框是**只写**的：默认掩码显示，点眼睛图标可以显示明文；已保存时会标出 **已保存**。没有改动过的字段不会重写已保存的值，留空保存会保留原值；要清除就点 **清除**。

### 模型

编辑器把模型分成两栏：左栏是 **可选模型** 选择器，右栏是所选模型的 **模型设置**。

Vibex **不预置模型列表**：

- **拉取模型** —— 需要已填 API Key 和地址，拉取该账号可用的模型来填充 **可选模型**。拉取本身不写入任何配置。
- **可选模型** —— 勾选一行会把这个模型加入草稿；取消勾选会移除它但保留已声明的能力，重新勾选即可恢复。**全选** / **全部启用** 可以批量处理；没有可拉取的模型时，在 **自定义模型** 里手动输入 id 再加入。
- **Model ID** / **显示名称** —— 在右栏编辑。选中状态按模型 id 跟踪，所以重命名之后右栏仍停在正在编辑的模型上。
- **模型接口协议** —— 每个模型可以单独指定通信协议，默认 **继承**（继承供应商设置）。
- **推理能力** / **思考档位** —— 选择是否推理，或声明**思考深度**档位。
- **上下文窗口 / 最大输出 Token** —— 在 **高级** 折叠区中声明模型上限。

供应商不提供的模型，右栏会显示 **添加该模型**，点它把该模型加入列表。

思考深度的可选档位来自供应商或 Agent 声明，常见取值为 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。声明错误会让 Agent 收到它不支持的档位；不确定时留空。

## 在会话中使用

发送消息前，从输入框顶部的级联菜单选择 **Agent**、**模型供应商**、**模型** 和 **思考深度**。如果 Agent 绑定的是路由组，模型列表里会出现路由组对外提供的模型名。

切换只影响后续运行；已有时间线保留原运行的 Agent 和模型信息。

<Warning>
  **测试连接** 和 **拉取模型** 会真实访问供应方网络并可能消耗额度。移动端的 `read_only` 设备不能触发这些操作。
</Warning>

## 故障排查

- **Agent 不在列表中**：确认可执行文件在 `PATH` 中，或检查自定义命令和参数。
- **模型不可选**：先 **刷新模型**，再检查该模型是否已启用，以及 Agent 是否绑定了包含它的 Provider 或路由组。
- **认证失败**：确认账号状态，重新登录；不要在 Issue 中粘贴响应头或 token。
- **远程端看不到配置**：确认设备权限级别是否为 `full_control`，以及当前连的是哪个权威运行时。本机和远程运行时的配置是分开的。
- **托管 Agent 安装失败**：检查网络是否能访问 GitHub 与运行时自己的分发源，然后重试。
- **Agent 收不到浏览器或电脑工具**：检查 Agent 的内置工具开关，以及电脑操作的总开关和驱动状态。
