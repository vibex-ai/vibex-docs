Vibex 为桌面端、Android、iOS 和自托管服务端提供现成的发布产物。**普通使用者不需要安装 Rust、Node.js 或 pnpm**：桌面端安装包是自包含的，TUI 也随桌面安装包一起发布。

所有产物都在同一个页面：

<Card title="下载最新版本" icon="download" href="https://github.com/vibex-ai/vibex/releases/latest">
  打开 GitHub Releases 的 latest 页面，选择与你平台匹配的产物。
</Card>

<Tip>
  Vibex 仍在候选阶段：除稳定版外，也可能发布形如 `-rc.N` 或 `-preview.N` 的预发布版本。**latest 页面会解析到当前最新的一个**；需要指定版本时改用 [全部发布列表](https://github.com/vibex-ai/vibex/releases)。
</Tip>

## 桌面端

| 平台 | 产物 | 说明 |
| --- | --- | --- |
| Linux x86_64 | `.deb` / `.AppImage` / AUR `vibex-bin` | 需要可用的 Vulkan 驱动 |
| Linux aarch64 | `.deb` | 该架构不提供 AppImage |
| macOS（Apple 芯片 / Intel） | `.dmg` | 需要较新的 macOS 与原生图形会话 |
| Windows x86_64 / ARM64 | `.exe`（NSIS） | 按当前用户安装，无需管理员权限 |

Linux 的 `.deb` 依赖 `libvulkan1`、`libxcb1`、`libxcb-xkb1`、`libxkbcommon0`、`libxkbcommon-x11-0`、`libdbus-1-3`、`libfontconfig1`，以及一个 appindicator 库（`libayatana-appindicator3-1` 或 `libappindicator3-1`）。发行版包管理器通常会自动解决这些依赖。

Arch 用户也可以从 AUR 安装 `vibex-bin`：它把审核过的 Linux `.deb` 重新打包，只在稳定版发布时更新，因此版本号永远与最新正式版一致。

<Warning>
  **macOS 与 Windows 的安装包没有经过公证或 Developer ID 签名。**
  - macOS 的应用包做了 **ad-hoc 签名**，Gatekeeper 不再报告它「已损坏」；但首次打开仍会提示来自未识别开发者：在 **访达** 里按住 Control 点击应用图标，选择**打开**，再确认一次即可。若仍被拦截，执行 `xattr -d com.apple.quarantine /Applications/Vibex*.app`。
  - Windows 会弹出 SmartScreen 提示：选择**更多信息** → **仍要运行**。

  ad-hoc 签名只保证包在组装后没有被改动，不能证明是谁构建的。每个产物旁边都提供了 `.sha256` 校验文件，`SHA256SUMS` 汇总了全部校验值。
</Warning>

### 发布通道

桌面端安装包带有**编译期确定的通道标识**，通道之间可以并存安装，互不干扰：

| 通道 | 产品名 | 数据目录 |
| --- | --- | --- |
| 预览 | Vibex 预览 | `desktop-preview` |
| RC | Vibex RC | `desktop-rc` |
| Stable | Vibex | `desktop-stable` |

每个通道有**独立的 SQLite 数据库和配置**。切换通道不会迁移数据；如果你在 RC 里配置好了 Agent 和供应商，装 Stable 之后需要重新配置一次。通道由安装包决定，不能在应用内切换。

### 升级

桌面端内置签名自动更新，**默认开启**。在 **设置 → 常规** 或 **设置 → 关于 → 软件更新** 中：

- 应用启动约 30 秒后自动检查一次，之后 RC / 预览通道每 2 小时、Stable 通道每 6 小时检查一次。
- 更新清单经过 Ed25519 签名校验，产物再做 SHA-256 校验，校验失败不会安装。
- 自动更新开启时，发现新版本会自动下载；已下载的版本可以在应用内立即安装，或在退出应用时安装。
- 关闭 **自动更新** 后，发现的新版本会等你确认；关闭 **更新提示** 后，标题栏按钮和浮层不再出现，但后台安全检查仍然运行。
- 安装方式取决于包格式：**AppImage 会原地自我替换**；`.deb`、macOS `.app` 和 NSIS 会**拉起系统安装器**，完成后需要重启应用。

只有同通道的版本会被接受：RC 安装包只看 `-rc.*` 版本。如果自动更新不可用，手动下载新安装包覆盖安装即可。

## Android

Android 客户端从 GitHub Releases 侧载安装：

1. 下载 `vibex-<版本>-android-arm64.apk`。
2. 在系统设置中允许来自该来源的安装。
3. 打开 APK 完成安装（应用 ID 为 `ai.vibex.mobile`）。

Android 客户端没有应用商店，更新也走同一份发布清单：

- 客户端只跟随 **Stable** 通道；预发布安装仍会知道它之后对应的稳定版。
- 应用会校验发布清单签名和 APK 的 SHA-256，然后把已暂存的文件交给系统安装器；Android 再校验签名密钥连续性。
- 可以在应用内下载并安装，也可以打开浏览器里的签名下载链接。
- 如果新 APK 的签名密钥与已安装版本不同，系统会拒绝覆盖安装。RC / 预览在未配置仓库密钥时使用一次性 CI 密钥，因此 **不同 RC 之间可能需要先卸载再安装**；卸载会清除本地配对凭据。

<Warning>
  **Stable 发布必须配置固定的 Android 发布密钥**。没有配置时发布流水线会失败，而不是悄悄生成一个无法覆盖升级的包。
</Warning>

## iOS

iOS 发布产物包括：

- `vibex-<版本>-ios-unsigned.ipa`：完整的 arm64 真机构建，**未签名**。
- `vibex-<版本>-ios-simulator.app.zip`：未签名模拟器构建。
- `vibex-<版本>-ios-xcframework.zip`：供集成使用。

iOS 拒绝运行未签名的代码，所以真机 IPA 需要安装者用自己的 Apple ID 重新签名。免费 Apple ID 的签名有效期为 7 天，到期后需要重新签名。

常见安装方式：

| 方式 | 说明 |
| --- | --- |
| **Sideloadly** | Windows 或 macOS，拖入 IPA，用免费 Apple ID 签名并通过 USB 安装。 |
| **AltStore / SideStore** | 用免费 Apple ID 签名并后台刷新；AltStore 需要一台常开的电脑，SideStore 可以设备内刷新。 |
| **Xcode 个人团队** | 打开工程，选择自己的 Apple ID 和 **Automatically manage signing**，直接跑到真机。 |
| **TrollStore** | 仅适用于 iOS 14.0–16.6.1 和 17.0；客户端要求 iOS 17.0+，所以只覆盖恰好 17.0 的设备。 |

从 [Unsigned iOS install guide](https://github.com/vibex-ai/vibex/blob/main/docs/operations/ios-unsigned-install.md) 可以看到完整的重签名步骤和校验方法。

<Warning>
  重签名会替换整个签名，不能证明二进制是谁构建的。只安装来自可信来源的 IPA。
</Warning>

## TUI

Vibex TUI 随桌面安装包一起发布，不需要单独下载：

| 平台 | 入口 |
| --- | --- |
| Linux | `.deb` / AppImage 里的 `/usr/bin/vibex` |
| macOS | `.app` 旁边的 `vibex`，安装器会链接到 `PATH` |
| Windows | NSIS 安装的 `vibex.exe` |
| 容器 | `docker exec -it <container> vibex-server tui` |

在项目目录里运行 `vibex` 即可。详见 [Vibex TUI](/tui)。

## 自托管

跨网络使用、或不想把会话数据留在某台常开的个人电脑上时，可以自建服务端：

- **[自托管无头运行时](/self-hosted-server)** —— `vibex-server` 是与你桌面端能力相同的权威运行时，适合放在服务器或家用常开机器上。
- **[SSH 与 WSL 远程运行时](/ssh-runtime)** —— 让桌面端通过 SSH 在另一台机器上安装运行时，或在本机 WSL2 里运行它。
- **[自托管 Relay](/relay)** —— 只转发端到端加密帧的中继，不做业务授权，也不保存业务数据。

服务端和 Relay 都发布了多架构容器镜像（`linux/amd64`、`linux/arm64`）。

## 卸载

| 平台 | 方式 |
| --- | --- |
| Linux（deb） | `sudo apt remove vibex-rc`（按通道替换包名） |
| Linux（AUR） | `sudo pacman -Rns vibex-bin` |
| Linux（AppImage） | 删除 AppImage 文件 |
| macOS | 把应用拖到废纸篓 |
| Windows | 使用“应用和功能”卸载 |
| Android | 在系统设置里卸载应用；会清除本地配对凭据 |
| iOS | 删除应用；重签名安装的版本到期后需要重新签名 |

卸载程序**不会**删除数据目录。要彻底清除，请先阅读[隐私与恢复](/privacy-and-recovery)，再手动删除对应通道的数据目录。
