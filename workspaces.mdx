---
title: "工作区"
description: "选择、切换和隔离 Vibex 的文件、Git 与 Agent 工作范围。"
---

工作区是 Vibex 读写文件、运行终端和执行 Git 操作的边界。桌面端会保存工作区元数据和当前选择；Agent 看到的文件范围也由工作区决定。

## 两种工作区模式

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| **CurrentCheckout** | 你希望直接在当前检出的分支上工作。 | 文件和 Git 操作作用于当前目录；多个会话可能看到同一份改动。 |
| **VibexWorktree** | 你希望把 Agent 改动与主检出隔离。 | Vibex 创建托管 Git worktree，提供合并、rebase、冲突处理和丢弃流程。 |

<Warning>
  在 **CurrentCheckout** 中运行多个 Agent 时，它们可能同时修改同一文件。需要并行尝试或评审时，优先选择 **VibexWorktree**。
</Warning>

## 打开或切换工作区

1. 在侧栏打开工作区选择器。
2. 选择已有仓库目录，或选择创建托管 worktree。
3. 确认工作区根目录和 Git 分支。
4. 打开文件、终端或会话时，检查顶部显示的当前工作区。

切换工作区不会把未提交改动复制到另一处。当前会话仍属于它创建时的工作区；切换前请保存文件并检查 Git 状态。

如果编辑器中存在未保存缓冲区，桌面端会先阻止切换并提示你保存或放弃。每次打开或切换工作区都会更新 generation；过期的文件、终端和 Git 请求会被拒绝，避免结果写入错误目录。

## 托管 worktree 生命周期

1. 创建 worktree 时选择基础分支和名称。
2. 在隔离目录中启动会话或手动编辑。
3. 用 **Git diff** 检查改动，并按需提交。
4. 选择合并或 rebase。发生冲突时逐文件处理，重新检查状态，再继续操作。
5. 确认主工作区结果后再丢弃 worktree；丢弃会删除隔离目录和未提交改动。

<Info>
  worktree 的路径、分支和状态由桌面端保存。移动端只能通过远程权限请求这些操作，不能自行创建本地 worktree。
</Info>

## 文件访问边界

- 文件树、内容搜索和编辑器只访问当前工作区范围。
- 文件服务会规范化路径并检查符号链接、编码、换行符和大小限制。
- Agent 的工具调用仍受权限和能力门控影响；打开工作区不等于自动授权所有操作。
- 终端默认绑定当前工作区，但可以在终端标签中切换工作目录。
- 远程请求还会携带工作区作用域和 generation；重连后以桌面端重新读取的状态为准。

## 常见问题

### 为什么 Agent 看不到我刚创建的文件？

确认文件保存到了当前工作区，并刷新文件树或重新打开会话。若文件在工作区外，需移动到工作区或在允许的情况下通过附件提供内容。

### 为什么 Git diff 没有显示改动？

检查是否切换到了另一个工作区或 worktree，确认文件已保存，再在终端运行 `git status --short`。
